# CRA System 开发约定

适用范围：本目录、专属 `.github/workflows/cra-system.yml` 和 `.devcontainer/cra-system/devcontainer.json`。不要改动新闻、内参、导演或其他项目。

## 接手顺序

1. 读 README、theory/BASELINE.md、theory/REQUIREMENTS.md。
2. 读 traceability/INDEX.md、architecture/SYSTEM.md，以及本次任务对应的模块文件。
3. 读 plan/WORK_PLAN.md 和 plan/tasks.json，从依赖已完成的首个未完成工作包推进。W00为工程基线；云端检查通过才可记验证完成。
4. 实现任务要求的代码和有价值的验收，不要不断重写计划代替开发，不跳过前置数据和权限工作。
5. 完成一个工作包后更新状态、实际代码/接口路径、测试证据和下一项。未运行的检查明确写未运行。

用户是临床试验专业人员。与用户讨论采用监查场景、底稿和具体操作，不让用户替开发者选择框架、数据库或算法。能从已授权资料取得的事实和规则先提取，关键冲突才请用户澄清。

## 固定边界

- 自动图像识别和逐字段比对仅限检验报告及EDC检验数据。其他资料可解析为规则、可人工引导记录，不扩展临床数据OCR范围。
- 所有list为关键要求→完整条件与例外→具体子项→原文。不能用笼统按方案替代已明确条款。
- CRC称已改和CRA验证正确分别保存；PD上报任务以用户明确已上报完成，不增加必须附回执的门槛，其他待办独立。
- 常规现场先复核遗留。未全部完成时的例外尚未详定，保留记录，不自行发明全局禁用锁；紧急事项不能被阻断。
- 访前信按模板选几项，不能把未选问题删除。交接不用复杂审批。
- 模型建议、CRA核实、研究者医学结论和原始事实分别存储。无证据不生成确定性正常、已完成或合规结论。
- 生成、实际发送/提交、签发和归档分别记录。本期不写回EDC、不自动外发或签名。
- 公开仓库只收合成数据和可公开文件。真实材料不进Git、不进公开CI日志；不得为测试调用含真实资料的模型。

## 变更与验证

业务理论编号CRA-Rxxx和模块编号Mxx永久保留，不能随意重排。理论修改后提高revision，更新对应设计及bindings指纹，在changes新增影响记录，再运行同步检查。仅润色也需说明是否影响技术；真正无需代码变更可写清理由，不强迫无意义重构。详细步骤见traceability/SYNC_POLICY.md。

依赖跨模块只通过公开服务/端口，不直接改其他模块表。接口变更更新API_CONTRACTS、DATA_MODEL、调用方和迁移。历史报告与原始来源不覆盖。更换OCR/模型实现不改变业务记录格式。

优先使用成熟依赖；从官方来源核对适用版本和许可证，生成锁文件后才称版本已锁定。不要复制第三方整个项目，不假定公开指南或岗位职责就是某家CRO内部SOP。实现完成不等于临床用途验证完成。

## 逐项编程执行

先读CODEX_START_HERE.md，再用python3 tools/next_task.py定位当前项，并读取对应plan/work_packages任务卡。默认V1A按顺序推进，阻塞或进行中的当前项不能自动跳过；OCR增强和实际部署单独选路线。用户明确只要设计/审阅时遵守该范围，进入编程后交付实际代码，不用反复增加计划替代实现。

plan/tasks.json是任务执行规范源，任务卡为生成视图。当前目标文件可以尚不存在；标verified前，目标产物必须实际存在、待实现命令已可运行、前置已完成，并保存实际证据。路径或接口合理调整后同步源清单和契约，不留第二份过时说明。只有基础工具、静态mock页面或文档不算业务功能完成。
