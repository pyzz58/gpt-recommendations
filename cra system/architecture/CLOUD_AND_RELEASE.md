# GitHub云上开发、运行和发布

## 1. 本轮云上产物

设计、理论映射、任务、示例核心和检查脚本直接通过GitHub API提交。没有要求用户在本地安装、复制仓库或运行命令。专属Actions在云上验证同步和基础行为；只检查本项目路径，不改动现有新闻/内参/导演流程。

GitHub要求工作流位于根级.github/workflows；Codespaces入口位于根级.devcontainer/cra-system。只有这两个平台入口在cra system之外，其余项目文件都在本目录。

## 2. Codespaces入口

在仓库Code → Codespaces → New with options中选择CRA System配置。配置文件为.devcontainer/cra-system/devcontainer.json，工作目录指向cra system，使用官方Python开发镜像，8000和5173端口保持private。

当前postCreate只执行基础检查，不启动后台临床服务，不安装或调用付费模型。W01/W02实现后，在此配置中增加数据库、API和前端，生成实际启动说明与健康检查。完整运行前不得声称已有网页可用。

开发与模拟可以在Codespaces完成；停机、休眠和存储生命周期不符合稳定生产托管需求，不能把它当作长期唯一临床数据保存点。正式试用采用获准的受控云环境，具体账户尚未配置。

## 3. CI与变更同步

专属工作流监听cra system、自己的工作流及Codespaces入口变化。使用只读仓库权限，checkout不保留令牌，不使用pull_request_target执行外来代码，不带真实数据/服务密钥。

检查步骤：理论映射与内容指纹→变更影响记录→Python测试→合成工作流演示。理论发生变化而对应技术未复核会失败。检查通过只证明这些工程条件，不代表临床验证。

可通过Actions页面手动运行基础检查；普通push/PR自动触发。测试不需要模型、数据库或外网凭证，不能在日志输出原始临床资料。后续集成测试依赖容器服务时使用合成数据和临时数据库。

## 4. 依赖与发布

W01/W02须生成Python和前端锁文件、固定运行镜像/版本、迁移脚本和SBOM；CI用锁文件安装。当前技术文档尚未选定所有精确补丁版本，不能把设计表格当作已完成锁定。

V1A发布要有完整工作流和已知能力说明；复杂OCR进入V1B后使用相同源字段及比对接口。正式部署至少配置身份提供者、TLS、私有文件/数据库、最小权限、备份恢复、保留删除规则和获准模型。应用数据库用户不采用超级用户或绕过RLS的角色；使用RLS时注意表拥有者的绕过规则并进行实际隔离测试。

真实项目资料上传前核实所用环境和服务获得授权。源码公开不等于数据公开，GitHub Secrets不能把公开日志或上传测试附件变成安全资料库。

## 5. 反馈如何回到理论

试用按一个实际工作场景提交反馈：发生了什么、预期怎样、目前怎样、关联CRA-R/M/工作包和去标识示例。先定位是规则资料缺口、理论变化、实现错误还是呈现问题，再更新对应位置。实现错误可修代码而不伪造理论变更；理论变化按SYNC_POLICY同步。后续不必推翻整套目录重做。
