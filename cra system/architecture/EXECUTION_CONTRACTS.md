# 跨模块执行、输入和输出契约

技术设计v0.4；业务依据为固定CRA-R条目及WORKFLOW_CONTRACTS，不新增临床要求。这里规定Codex实际实现时如何连接模块。目标对象按各任务增量迁移，不在W01一次创建全部未来表。

## 1. 同一次判断必须绑定的上下文

ExecutionContext含tenant/study/site/subject范围、purpose、当前操作者及角色、clinical_event_time（含精度/未知）、monitoring_visit_id、input_revisions和适用规则快照。服务端根据身份推导可访问范围，不能信任浏览器自行传入的actor或tenant。来源事实、自动提取候选、系统推断和用户确认分别存储，不能互相覆盖。

同一项目/中心内也要先完成源报告和EDC受试者标识映射；仅有相同姓名、日期或数值不能确认为同一记录。跨研究/中心链接由复合约束及服务校验共同防止。未能匹配可以先保存/提取文件，但不自动进行相应患者间对照。

## 2. 每次输出共用的结构

OutputEnvelope由W02建立类型，M03解析规则适用性，业务模块生成语义，M11只组合已记录事实。provider不能绕过该结构直接向页面或报告提交确定性结论。

| 字段 | 最小内容 | 负责者 |
| --- | --- | --- |
| output_id/purpose | 当前输出及用途：规则候选、窗口、比较、分析、提醒、报告草稿等 | 调用业务模块 |
| scope/input_revisions | 研究/中心/患者、覆盖字段/期间/快照与输入修订 | M01授权，业务模块保存 |
| policy_versions | 共性/项目/中心实际适用规则与VersionActivation；未提供项保留缺口 | M03 |
| claims | 分类fact/auto_candidate/inference/user_confirmation、文本/结构值、引用、计算/核实状态 | 对应业务模块 |
| evidence_refs | 文档版本/锚点、Excel行、源图区域、用户动作、原记录及修订 | M02/M04/M07/M08/M06 |
| unknowns/conflicts/not_checked | 未知原因、真冲突、用户跳过的明确范围及可继续部分 | 产生该事项的模块 |
| capability/status | implemented/configured/validated等能力信息，ready_to_review/limited/needs_clarification | M14能力，业务模块表达 |
| generated_at/actor | 实际生成时间及操作主体，自动动作另标worker/provider | M01/平台 |

三层约束按用途应用，不要求每条提醒检索全部文件；已核实适用规则快照可复用。没有规则或定位时允许保存真实差异、事实、待澄清项和有限范围草稿，不生成确定性正常/无AE/全部合规。CRA点击确认整改是有效用户动作依据，不因缺附件、CRC回复或额外复核表被共享校验拒绝。OutputEnvelope不是新增审批或自动外发许可。

## 3. 各用途最低输入

| 用途 | 必要输入 | 可缺少并明确限制的内容 | 缺口行为 |
| --- | --- | --- | --- |
| 展示遗留 | 已有Issue或历史文件候选、当前中心、未完动作 | 旧记录缺位置/整改出处/修改细节 | 保留unknown，可展开/补充，不编造历史 |
| 数值对照 | 唯一身份/检验实例、可读两侧值、必要单位/比较符 | 与本次值比较无关的治疗锚点 | 继续可比较字段；身份或单位歧义则相应部分待核实 |
| 窗口判断 | 适用规则、明确计算口径、实际锚点与检查时间及精度 | 不影响本窗口的其他病史 | 提示补充；拒绝后跳过依赖路径，不停其他核查 |
| 安全分析支持 | 所问维度的项目规则、相关事实与来源 | 未提供病史/研究者评价/IB等 | 保留具体缺口和分析范围，不猜补或写无AE |
| Query超期 | 真实创建日期、适用期限依据、当前实际状态 | 未知的回复细节 | 期限未知只显示待明确，不造超期天数 |
| 目录对照 | 上传目录原文件/版本和当前中心 | 尚未结构化目录条目 | 原文件对照和简单状态可用，不强迫重录 |
| 报告 | 用户模板映射、本次范围、事实/问题/动作引用 | 模板字段所需事实尚缺 | 草稿明确缺口，不用无异常填空；签发快照不覆盖 |

ContextImport支持授权结构化JSON与CSV/XLSX映射。最小字段为subject_external_id、fact_key、value_raw、observed_on及source_ref，unit、precision、repeat_instance等按事实类型可选；study/site从可信范围补全。治疗实际日期等只补需要的事实，不要求先重建全部病历。已有事实直接复用；导入缺日期不补时分秒。此结构化输入不扩大用药/样本的临床OCR范围。

SafetyContext按评估维度列needed_fact_keys。检验异常本身、AE是否记录、研究者判断分别表达；EDC检验表不包含AE资料时，不能推断未发生或未记录AE。项目实际采用的分级/严重性/相关性/预期性/AESI/DLT规则由M03给出，M09不写死另一套标准。

## 4. 原子操作、异步作业和版本

普通写操作为授权→读取revision→业务校验→更新+audit同事务提交；expected_revision过期返回409。幂等键绑定actor/范围/命令/输入摘要，相同输入重试回原结果，不同输入复用同键冲突。ORM版本计数不能代替所有批量更新的显式版本条件。

文件上传先取得私有对象引用并校验大小/类型/哈希，登记版本后入持久job；解析worker按租约领取、重鉴权、受限处理、提交输出及outbox。处理中断可重试；无法保证调用外部provider绝不重复计费，必须记录attempt/provider_request_id与实际成本，已缓存成功结果优先复用，不能宣称端到端exactly-once。

每job绑定输入文档/映射/规则版本。处理期间输入已更新时，旧job结果保留为旧版本，不直接成为当前结论；只提示或安排关联重算。确认字段或匹配修改后，仅相应Comparison/Assessment待重算。撤销权限后停止读取/输出相关文件。

## 5. 模板和历史

TemplateMapping显式规定输出类型（DOCX报告/信件或XLSX track）、字段、重复问题区、覆盖区、来源附注、必填/可空及显示策略。优先支持有明确映射的模板；复杂布局/内容控件/宏等逐项列支持范围，不能承诺任意上传模板自动完美还原。模板不执行宏。

报告从稳定Issue/Action/Coverage/Assessment取快照，正文与track保持同一事实。用户语言修改不回写医学事实；需要改事实时走事实修订。VersionActivation按临床事件日期选择依据，报告生成时另存输出要求；2021年后生成的报告可以包含此前事件和此前依据。用户点击确认记为CRA确认，不虚称AI独立验证。生成、实际发送/提交、签发/归档分开。

## 6. 模块连接和后续变更

M02来源→M03规则→M04患者/时间→M05工作区；M06独立问题服务供所有阶段使用。M07→M08只处理检验自动对照，M09消费已知事实和规则，M10原目录/简单状态到W10启用，M11组合输出。M12为能力端口，M13为工程同步，M14为平台/验证。

M05的目录状态不是W06硬依赖；未启用M10时可直接查看M02目录原文件。新增临床条款通常只改运行时RuleVersion，新增无法表达的条件才扩展契约和测试。API由实际FastAPI导出并生成前端类型；数据变化通过兼容迁移，来源和已签发快照不能就地覆盖。

## 7. 共性规则包与启用日的边界

CommonPolicySet保存产品固定权限/来源/状态控制及适用GCP等原文依据索引、法域、官方版本/效力日期、来源取得状态和审核范围。项目/中心规则不能降低共同底线。M03必须能装载并定位该包，不能用模型记忆或空白“GCP已检查”标记代替；实际未提供条款时保留未知，不能宣称完整共性合规核查已做。

用户手动输入的是项目或中心实际开始使用日期；法律正式生效时间、批准要求、资料发布、培训和上传时间分别保存。手动日期不能无依据改写官方效力或正式批准条件。发生冲突时显示来源及影响，记录现状和其他工作仍可继续，不增加确认整改的材料门槛。
