# 检验自动化的完整实现路径

技术设计v0.4，对应M07/M08/M09/M12与W03/W07—W09/W13/W14。第一版自动读取与比较是主线；以下支持范围是开发目标，必须经实测后才能列为可用能力。

## 1. 输入支持与早期可行性

首批目标：清晰打印检验报告的文字PDF、扫描PDF和JPEG/PNG照片，以及EDC检验XLSX导出。以具有代表性的血常规/生化等排版样例验证行列归属，不能把文字PDF成功等同于照片成功。手写、严重模糊、遮挡和未验证版式明确标范围外，用户可少量补录或跳过；支持范围根据反馈扩展。

W03先建立纯合成样本和环境探测：实际安装依赖、加载模型、读取图片、输出坐标/表格结构，记录Python/推理引擎/模型版本、CPU内存、耗时和失败。OCR包的最低Python版本不等于所选推理引擎和全部依赖在Python3.13可用。

常规API与编排worker仍采用同一应用代码；OCR优先经独立adapter调用。若OCR依赖与主应用冲突，只隔离识别运行环境/容器并锁版本，不重写患者、规则或报告，不为此拆成大量服务。W08前必须有可运行候选，不能等所有页面做完才第一次试装。

## 2. 处理步骤

| 步骤 | 具体实现 | 必须输出 |
| --- | --- | --- |
| 接收源文件 | 私有对象、版本/哈希、页数/格式/尺寸检查，禁止执行嵌入内容 | LabReportVersion和job |
| 路由 | 文字PDF先读字符/表格，扫描和照片走图像管道；必要时页级分流 | 每页处理方式与覆盖 |
| 图像预处理 | 方向、裁切、质量检查；原图不覆盖，变换保留坐标映射 | 原页与处理页可回查 |
| OCR与结构 | 文字块+行列/单元格归属；重建项目、结果、单位、范围及日期的关系 | 原文、坐标、结构候选 |
| 字段标准化 | 原始字符串保留，Decimal/比较符/单位/参考范围有类型；别名采用版本化映射 | typed observations及失败原因 |
| 身份和实例匹配 | 中心/受试者映射、项目、采样时间精度、初检复查、修订报告、必要访视 | unique/ambiguous/unmatched |
| 自动比较 | 按可比字段及已批准转换规则计算，不用数值相近决定匹配 | 一致/差异/单位待核实/未见/未知/跳过 |
| 异常展开 | M09读取项目规则和上下文，给具体线索及待核实问题 | 有来源的候选分析和后续动作 |
| 用户处理 | 集中看差异/歧义/低可信，正常范围批量确认，少量纠错或跳过 | 用户动作、来源、范围与修订 |
| 下游输出 | 差异关联M06，结论和覆盖交M11，不再重抄 | 稳定问题编号、报告/track引用 |

程序读取文字和表格不必绑定大模型。基础方案优先评估PaddleOCR及结构识别；多模态模型可作为获授权的替代/困难案例适配器。具体模型由代表性样本的关键错误、复核负担、资源和数据处理条件决定，不能凭宣传指标或模型自报置信度选择。项目规则提取与综合解释另经ExtractRules/AnalyzeCase端口实现，不与OCR供应商绑定。

## 3. 字段、匹配和区间语义

保留raw_text/value_raw、value_type（exact/bound/interval/text）、operator、decimal_value、unit_raw/normalized、LLN/ULN及其适用信息、collected_at/report_at精度、source_anchor、extraction_state和validation_state。未提供参考范围保持unknown；不能借EDC数值“纠正”源识别后再声称一致。

“<某值”等受限值按区间比较，不能转成该值再比较。文本阳性/阴性等采用明确映射，不能默认等同数字。可换算单位须带已确认转换和适用条件；不同单位/方法不可自动比。初检、复查、补发及修订保持实例关系，日期精度不足有多个候选时保留歧义。

只有文字识别准确而行列归属错误仍算关键失败。身份/时间/项目错配、不正确单位换算、小数点/比较符误读和漏读关键异常分别统计；平均字符正确率不能替代这些指标。

## 4. 用户负担与状态

自动字段、用户更正和用户已核实分别保存。通过结构、来源和匹配校验的字段可自动形成范围明确的比较候选；低可信/歧义/异常集中查看，正常范围批量确认，不能要求全量手抄或每个正常字段点击。

缺锚点只停止窗口路径；身份不明只停止对应对象比较。用户拒绝补充或说不用管时保存CheckDecision和范围，停止依赖判断与反复追问，其他事项继续，不自动生成整改催办。识别不可用时保留原文件、既有问题和list；大规模手动兜底应判核心自动能力未达标，不能重新命名为完整自动版。

## 5. 支持范围与实际评估

SupportProfile至少记录格式/版式/图像条件、pipeline/provider/model/映射版本、评估样本及分组、关键错误、自动可用比例、人工更正/补录比例、确认和返工总时间、限制及评估日期。以同一资料任务的原工作流程比较总耗时，不预设没有证据的节时比例。

开发样例用于调试，独立评估样例保留预先标注的正确身份、日期、字段和应出现的问题；评估时不将预期送入模型。纯合成数据只能证明所覆盖条件；获授权真实格式试用由W15补充，不把两者混为一项。

W08必须完成首批支持范围的实际识别→匹配→比较评估，W09补安全分析支持；W13汇总范围和全部工作时间。W14只增强已有能力的复杂格式并重新回归，不能后置第一次OCR。实际错误或负担不合格时调整adapter/范围和任务实现，固定理论/问题编号及历史不重建。
