# 成熟开源组件复用与模块替代

技术修订v0.5；核对日期2026-10-29。基准：`99b300f00f20af22c88770f0fdad7618c3e43ee1`。逐项来源、许可证文件和上游提交见[reuse-catalog.json](reuse-catalog.json)。本轮核对14个原始仓库、文档、许可证及部分发布记录，没有安装依赖、运行OCR/第三方服务或把业务任务改为完成。

## 1. 结论与采用顺序

可以直接复用多数通用能力，但“现成”应落实到具体包、接口和服务，不能只把一个完整项目名称放到图里。当前最有价值的是OCR/表格结构、PostgreSQL任务队列、Word模板渲染、核对表格、源PDF查看、OIDC客户端和S3客户端。

保留FastAPI/React、PostgreSQL/SQLAlchemy/Alembic及现有python-docx/pdfplumber/openpyxl路线，不重写ORM、迁移、PDF绘制、表格控件、OCR引擎或后台队列。CRA的规则适用、数据匹配、用户确认和报告事实仍通过本系统业务服务实现。没有找到经本轮验证能整套覆盖本产品约定的CRA成品系统，不把EDC/CDM平台等同于本产品。

“采用”是技术选择，实际安装和集成在对应工作包进行；需要推理/复杂解析的组件先通过样本和运行环境门槛，不能凭stars或官方通用准确率宣称临床适用。

## 3. 不能跳过的适配细节

### 检验和规则资料

PaddleOCR的结构管道能提供更细的文字/单元格位置，但通用基准不是检验字段、身份/时间和异常判断的正确率。当前README的Python徽标也不能证明与主应用3.13的全部依赖兼容。W03优先以隔离的可用运行环境（可先评估3.12）试装，实际锁定推理引擎和模型；不要因此重写主应用或扩大非检验OCR。

Docling具备多格式、版面/表格、OCR和本地处理能力，代码MIT，但其原README明确模型需分别看原包许可。对方案/IB，必须测试合并单元格、脚注、否定/前提/例外、样式含义和可回查锚点；输出Markdown成功不是全量保留证明。首版先对照同一小样本，不预设它一定胜过现有解析组合。只选实测合适的后端，输出统一SourceAnchor/候选字段，不让供应商数据结构成为业务库格式。

### 队列和事务

Procrastinate接替通用调度机制，不接管临床Job状态。任务参数只传内部引用ID，worker重新检查授权和输入修订。失败、重复和权限撤销均走业务服务；不让队列日志携带整份报告或患者原文。

上游当前main文档给出了外部连接与特定SQLAlchemy connector的原子入队方式，但这不是所有已发布版本/驱动的保证。W03核实实际锁定版本。若无法证明与本系统SQLAlchemy/psycopg组合共享同一事务，默认保留业务写入＋Outbox同事务，relay再交Procrastinate并幂等处理；不能分别提交后声称原子。崩溃重试仍可能重复执行外部调用，不宣称exactly-once。

### Word/Excel和界面

docxtpl使用模板标记，有同一run及特殊段落/表格语法限制。由一次TemplateMapping或准备模板完成字段/问题区映射，不能要求用户每次重新整理。只开放受控变量/循环/过滤器，数据来自业务DTO；模板不取得文件系统/网络/数据库权限，渲染使用受限环境和资源预算。输出检查中文样式、表格、页眉页脚、来源和未核实范围，生成不等于签发。

AG Grid根仓库同时含MIT和商业包。默认只装ag-grid-community/ag-grid-react，不导入Enterprise。Excel Export、某些分组/剪贴板/服务端高级功能属另一许可范围；后端openpyxl输出track，不依赖收费导出。React-PDF的worker与主包版本、浏览器和字库需实测，不能把第三方CDN作为私有源文件的展示依赖。

Authlib采用BSD许可路径；Keycloak仅作为没有既有身份服务时的可选方案，不强迫首个数据库任务就部署Java身份服务器。认证成功后仍需本系统按授权范围限制来源、检索、比较和导出。

## 4. 已检索但不作为默认依赖

| 项目 | 判断及理由 |
| --- | --- |
| Docling | 重要对照候选，先证明来源完整和资源可用；不直接整个替掉M02/M08 |
| FastAPI Full Stack Template | MIT，活跃且有完整应用参考；其SQLModel/账号和本项目SQLAlchemy/OIDC/三层范围/证据链不同。可按许可参考构建和部署文件，不整仓覆盖当前项目 |
| GoRules ZEN | MIT，有Python绑定/决策表；需证明unknown三值逻辑、Decimal/单位、历史版本和来源等价，暂不把新规则引擎加成首版依赖；保留已有有限AST |
| Microsoft MarkItDown | MIT，可辅助文本/Markdown转换；官方说明不以高保真人类文档转换为目标，不能单独承担精确证据解析 |
| LibreClinica | EDC/CDM且已有Java/Tomcat体系；本系统读取既有EDC导出，整套引入会改变范围和部署负担。本轮不部署、不替换EDC |
| Keycloak | 成熟身份服务可选，已有OIDC则直接用Authlib接入；避免为演示提前新增基础设施 |
| XlsxWriter | BSD-2-Clause，适合全新Excel输出；官方明确不能读取/修改已有Excel，当前有模板需求，继续openpyxl为主 |

Dify/RAG平台、多Agent框架、向量数据库和完整CTMS未被本轮结果证明是必要替代。当前模型只经受限提取/分析端口调用；本轮不为了复用另建第二套资料库、权限、问题状态或聊天工作流。

## 5. 哪些临床能力仍需写

- M03：共性/项目/中心适用性、启用日期、条件分支/例外、三值未知、用户增删及精确出处。通用规则引擎没有本项目资料内容。
- M04/M07/M08：患者与两侧标识、实际日期精度、初检复查/修订匹配、单位/区间、快照范围和局部跳过。
- M06：开始遗留提醒、展开来龙去脉、CRA点击确认、PD已上报和其他整改分别完成、跨次同编号。
- M09：按实际项目标准形成安全/AE/PD分析线索，区分系统候选与医学答复。
- M11：同一事实生成信件/报告/track，覆盖与未知措辞、用户确认来源及历史快照。

以上是产品差异所在。复用组件减少通用工程，不能让组件默认行为改写这些理论。

## 6. 许可证、维护与安装记录

本轮来源清单包含原仓库、不可变HEAD、最后推送/归档、许可证路径及部分发布快照，不以stars作为选择门槛。14个仓库本轮均未归档，但维护活跃不等于安全或临床验证。未取得完整许可文件的未选项目如实注明仅元数据核对。

- AG Grid按包许可，docxtpl为LGPL-2.1-only，其余各项许可见目录；代码许可、模型权重、传递依赖和外部API条款分开记录。
- 调研HEAD不是安装pin。GitHub的latest release在monorepo可能对应其他语言包，boto3该字段也可能历史滞后；实际安装包/镜像/模型摘要在对应工作包核实并写锁文件及依赖台账。
- 不下载所有候选，不复制整仓，不改45条业务理论或16个任务编号，不引入自动收费/外发/EDC写回。
- 若成熟组件在规定样本、权限、数据或运行环境下不适用，Codex记录具体失败，再选择已列对照/薄适配方案；不静默退回大规模人工录入或更改理论。
