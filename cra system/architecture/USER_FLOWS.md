# 界面与实际工作场景

这是待实现的页面方案，用于W02/W12；本轮未创建可使用的网页。界面使用临床工作语言，不显示模型链、数据库、映射ID等内部细节给普通CRA，除非查看来源或错误确有需要。

## 1. 项目入口

项目和中心→选择启动/监查访视/中心关闭/交接。显示资料版本及实际缺口，已有患者和历史问题自动带出。新增规则文件、项目邮件/文字和目录分别标明用途，避免与患者笔记混淆。

## 2. 访前准备

左侧为完整遗留问题，右侧为用户模板预览。系统提出几个相关候选，CRA可调整勾选，不固定统一条数。未选问题仍在完整列表。生成访视信草稿后可复制或导出；实际已发送由用户按情况记录。

## 3. 到中心复核遗留

默认先展示上次未完成及已回复待验证项。每条展开：原问题/位置→整改建议及具体出处→中心回复与实际修改→CRA核实是否正确→剩余动作。一个问题有多个动作时分别呈现，例如“PD上报已完成，数据更正仍待复核”。

复核通过后进入已确认的正常新监查流程。尚有未完时保持可见，不自动删问题，也不替用户制定所有现场例外或添加复杂审批。紧急事项入口始终可记录处理。

## 4. 受试者工作区

患者列表显示核查断点。打开一名患者后，中间是本阶段分层list，右侧可看原文；检验核对时并排显示源报告和EDC记录。关键摘要直接显示数字、时间、例外及版本，点开查看完整条件和子项。

正常内容按范围快速简记；差异、异常、缺件才详细记录。识别失败提供人工补录和本次跳过，跳过后不重复追问。匹配存在同日初检/复查歧义时只针对关键身份信息核实，不能靠数值近似擅选。

## 5. 分析与待办

显示事实、规则依据、初步分析及具体需核实问题，用户可记录研究者或医学答复。系统建议和实际答复分开；必要上报或紧急提示直接显示依据。新增问题自动进入报告待办，不用重复抄写。

## 6. 中心共同事项、报告与下次

ISF/TMF展示上次缺件和本次变化，用户说明是否补齐。报告预览分“上次遗留处理”和“本次核查发现”，并明确本次范围。提交、签发等实际状态由相应操作记录；track从同一记录生成。

下一次打开后继续沿用问题编号、过程和核查断点。交接只给无遗留说明或清楚的遗留来龙去脉及后续工作；关闭模块按项目资料展示，不替项目组批准。
