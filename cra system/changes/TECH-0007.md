# TECH-0007 CRA-W02 API and workbench shell

Date: 2026-10-31.

This technical change implements the existing CRA-W02 scope without altering the
45 fixed business requirements or starting later clinical modules.

## Delivered

- FastAPI application with uniform errors, request IDs, security headers,
  health/readiness/capability endpoints and generated OpenAPI.
- Authlib OIDC adapter plus signed HttpOnly sessions. Synthetic login is limited
  to synthetic/test environments and always uses server-configured identity;
  production rejects synthetic login and client-supplied identity headers.
- `GET /api/v1/me/scopes` obtains actor and tenant only from the trusted session,
  then returns only W01-authorized studies, centers and roles.
- React/TypeScript/Vite shell with login/error states, project/center selection,
  refresh persistence, an explicit unavailable-provider banner and no fabricated
  clinical result.
- OpenAPI contract and frontend type generation/check scripts.
- Truthful capability reporting and a shared OutputEnvelope that keeps facts,
  automatic candidates, inferences and user confirmations separate.
- Codespaces/Codespace-compatible Node, Docker, PostgreSQL bootstrap, migration
  and synthetic seed configuration.

No database table is added in W02; identity sessions are signed and the project/
center authorization store remains the W01 migration.

## Verification ownership

`tests/api/test_platform.py` uses FastAPI against disposable PostgreSQL 18 and
the real W01 governance service. The `cra-w02` job also runs frontend tests,
typecheck, production build, OpenAPI drift check and a runtime smoke that starts
FastAPI, authenticates a synthetic session, reads authorized scopes and serves
the Vite shell.
