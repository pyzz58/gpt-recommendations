## 1. 用户已确认的内容

1. 正常使用需要能输入并保存项目编号、项目名称、中心编号和中心名称，再开展监查，而不只选择开发者预置的演示项目。
2. 项目和中心选择固定在工作台左上角；同一项目可有多个中心，并可切换。
3. 项目、中心选择下方展示当前范围的业务模块；右侧展示选中模块的具体内容、记录和操作。
4. “访视前”是独立入口，排在“本次监查”之前。
5. “本次监查”按报告模板中的章节和问句组织核查项，并能在当前上下文上传 EDC 与检验源报告、查看比对、记录核实及后续待办，回填相应报告位置。

用户认可的是上述交互与业务衔接。示意中的合成名称、数值、模块数量和某中心的阶段组合不是新的临床规则、权限策略或硬编码配置要求。

## 3. 工作台结构

| 位置 | 内容与行为 |
| --- | --- |
| 左上角 | 当前项目选择、当前中心选择、新建项目和新建中心入口 |
| 左侧下方 | 当前项目/中心的资料与模板、启动、访视前、本次监查、报告与遗留、关闭/交接等业务入口；沿用原业务模块，具体组合依已配置范围呈现 |
| 右侧 | 当前模块的核查项、依据、文件、核对结果、记录和待办 |
| 跨模块 | 延续同一项目、中心和本次监查；按业务需要选受试者和检验实例，避免反复填写 |

项目与中心的“选择”和“创建”须分开。空数据库或当前项目没有中心时，具有相应权限的人应有清晰的建立入口，而不是要求开发者手动改种子脚本。正式权限仍由服务端身份和既有角色判断；不能把所有 CRA 提升为全局管理员。合成环境可使用明确受限的管理身份完成体验。

模块导航不是全局完成门禁。新中心、无上次遗留、未生成报告等状态通过空状态和下一步动作说明；不因遗留未完成或某阶段尚未结束而封锁紧急事项。未配置的模块或自动能力如实说明，不展示假完成。

切换项目/中心时，右侧数据、受试者选择、源报告、EDC快照、比较、模板和本次监查都须切到对应范围。旧请求晚返回、旧缓存、浏览器历史或未保存编辑不能造成串线或静默丢失。刷新和重新登录后从服务端恢复，而不只修改顶部名称。

## 4. 访视前与本次监查

### 访视前

复用既有遗留和报告服务：

- 完整接续上次遗留，首次可从既有报告、track或问题文字整理。
- 按用户模板选几项进入访前信；未选问题仍在完整遗留中。
- 保存本次范围和准备事项，复用已有项目/中心资料。
- 生成可编辑的访前信草稿；生成与实际发送继续分别记录。
- 无上次遗留的新中心也可继续准备本次访视。

### 本次监查

现场工作先呈现遗留复核，再进入新的核查；保留直接处理紧急事项的路径。右侧按已确认报告模板的章节和问句组织核查项，允许展开：

- 当前核查问题及完整条件、例外、子项和原文；
- 已有资料、对应受试者/访视/检验实例；
- EDC Excel 与检验源报告的导入、读取和比对；
- CRA 核查记录、已核查/待核实/不适用/未核查等实际状态；
- 已发现问题、分项行动及其后续追踪；
- 对应报告章节和当前草稿。

模板问句是“待核查项”，不是一创建就认定已发现的问题。模板决定章节和回填位置；共性、方案/IB、监查计划、项目补充资料与中心要求共同决定应查内容。模板未列而仍适用的要求要保留为补充核查，不得被模板过滤掉。

## 5. 模板与记录关联

1. 支持范围内的普通 DOCX/XLSX 模板先提取章节、问句、表格行和来源位置，形成可集中修订的候选；保留无法稳定解析的内容与覆盖缺口。不要要求 CRA 手写 Jinja、JSON 或 AST。
2. 首次配置集中确认结构和对应关系，按项目/中心、模板版本保存并复用；不是每次监查重建或每项机械重复确认。
3. 核查项关联模板版本/位置、适用规则和核查记录；同一事实、问题、行动继续由既有服务维护，报告读取同源记录，不复制第二套完成状态。
4. 模板升级保留历史。已签发报告使用当时快照；新模板不覆盖旧报告，也不静默改变旧核查项的含义。
5. 未核查、未知、用户跳过、无法比较和待核实继续分别表达，不自动回填“正常”“合规”或“已完成”。

实现可增量完善模板/核查项映射，但不得用只给合成样例写死问题列表来宣称支持模板驱动核查。新字段或持久关联确有需要时，按原模块边界补迁移和契约。
