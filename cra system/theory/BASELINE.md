# 第一版业务理论基线

基线 CRA-V1-20261029，业务修订 v0.3。来源为Notion v0.14及2026-10-29用户八点澄清。完整规范见[固定理论](REQUIREMENTS.md)，本轮决定见[八点记录](DECISIONS_20261029.md)。与旧的“人工版先验收、OCR以后再做”或额外整改证明要求冲突时，以本次确认内容为准。

## 目标和工作顺序

CRA应接着上次工作做，看到适用于当前项目、中心、受试者和阶段的要求，减少遗漏及实际总工作量。

1. 访前整理完整遗留，按用户模板选几项写访前信；未选问题仍保留。
2. 本次开始提醒核查遗留，点击每项查看原问题、具体位置、整改建议及出处、已有沟通/修改与后续事项。首次可从上次报告、track或已有文字自动整理，不要求全量重抄。
3. CRA与CRC当面沟通核查后，点击“确认整改”即可完成所选事项。系统自动记人和时间，补充说明可选，不要求预录CRC回复、附件、前后对照表或另一次审批。用户确认不写成AI独立验证。
4. 按常规先处理遗留再进入新的受试者核查；系统保留导航和提醒，未完事项仍显示，不设全局禁用锁。紧急事项可及时处理。
5. 打开一名受试者→显示本阶段分层list→系统自动读取检验源报告及EDC Excel→先匹配再核对→异常展开相关规则和具体问题→用户记录核实及待办→带入报告→下次接续。

## list、资料和版本

共性—项目—中心三层适用要求共同参与。资料包括方案、IB、SOP、Q&A、监查计划、手册、项目邮件/文字、目录与模板。明确按规则用途提交的文字无冲突时直接纳入，不因媒介重复确认。

每条list为关键要求→完整条件与例外→具体事项子清单→原文依据。子项包含前提、触发、不同分支、后续动作及完成方式，例如条件C走路径B、条件D走路径F。模型应尽可能完整提取资料已明确的结构，用户确认增删，实际使用中继续完善；没有依据的分支标待完善，不凭空补齐。

用户可手动设定新方案或其他规则资料在项目/中心的开始使用日期。按事件时间选择当时适用版本，起始日含当天；上传时间不代替开始使用时间。新报告可以引用不同历史事件各自依据，已签发报告不覆盖。用户录错或之后更正启用日时保存修订并定位受影响事项。

## 核心自动化和缺口处理

检验报告自动读取、字段提取、与EDC Excel核对一致性/逻辑性及提供安全分析线索，是第一版核心能力之一。自动图片识别和逐字段核对仅限检验报告；用药、样本等仍可人工引导与记录，不扩大本期范围。

手动补录仅处理少量不能识别或缺少的资料。大规模抄录或逐字段机械确认不能视为实现减负。W08须包含支持格式的自动读取与比对，W14只增强复杂格式；内部人工模式不代表核心自动版已完成。

缺数据时针对性提示补充；用户明确拒绝或“不用管”表示知晓，停止相关依赖路径及反复追问，其他核查继续。保存跳过范围并允许主动恢复；跳过不写正常、不当作未整改问题持续催办。

系统主动给出基本分析、具体依据和待核实问题；最终医学判断由适当人员完成。分级、严重性、相关性、预期性、DLT等分别保存，不相互推断。

## 问题、文件与报告

PD需要上报时附依据提醒，用户明确说已上报即完成该上报动作；其他动作各自更新。正式EDC Query与系统草稿分开，超期须有真实日期与项目时限。

ISF/TMF第一版可将用户上传目录直接作为对照文件，附简单缺件与进展；不要求先重建整套目录或文件平台。目录、文件存在和内容是否适用不混为一个状态。

启动、访视、关闭、交接共用资料和问题。关闭依项目资料与项目组意见；交接只说明无遗留，或遗留前因后果、现状及后续工作，不加复杂审批。

报告、信件和track来自同一记录。用户确认状态如实进入草稿及下一次提醒；已签发报告保存当时快照。生成文件不等于实际发送、上报或签发。

## 验收与迭代

分别记录代码完成、合成验证、实际识别/模型验证和获授权试用。使用代表性样本检查错读、错配、漏条件、错误结论；测量导入、确认、补录、核对、报告及返工的总耗时。复杂格式可增量扩展，不能用大量人工兜底掩盖自动能力不足。

缺IB、Q&A、实际SOP、目录、模板及部署授权时，开发使用合成案例并标明缺口，不能把合成要求写成项目已批准规则。真实资料不提交公开仓库。后续按[同步规则](../traceability/SYNC_POLICY.md)更新对应理论、模块、任务和证据。
