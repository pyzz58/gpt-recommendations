# CRA-W09 completion record

Status: verified. Date: 2026-11-01.

This record covers evidence-grounded AE, SAE, special-standard and
protocol-deviation analysis support for the declared synthetic/provider scope.
It is engineering validation, not clinical validation or proof of workflow time
savings.

## Delivered

- PostgreSQL migration `migrations/versions/0008_safety_assessment.py` adds
  immutable safety assessments, separately persisted dimension results,
  append-only CRA reviews, independent medical responses and explicit M06 issue
  links. A database check also restricts the supported event types.
- `backend/cra_app/safety/service.py` consumes current source/confirmation
  status from M04, event-date applicable confirmed rules from M03, comparisons
  from M08 and safety skip decisions from M05. Only `original_record` and
  `cra_confirmed` facts can drive deterministic findings.
- AE collection, grading, SAE seriousness, investigator relatedness,
  expectedness, AESI, DLT, protocol deviation and reporting timeliness are
  separately evaluated and stored. A grade condition does not create a
  seriousness candidate.
- Specific questions and urgent reminders are generated by the service.
  Event, awareness, entry and actual reporting dates remain separate. Without
  awareness time or an applicable project deadline, the service does not
  calculate lateness.
- `backend/cra_app/safety/grounding.py` rejects malformed output, unapproved
  explanation codes, fabricated/unknown evidence IDs, unsupported numbers or
  dates, and medical/safety conclusions outside the review boundary.
- `backend/cra_app/providers/case_analysis.py` and `case_worker.py` run the
  pinned `Qwen/Qwen2.5-0.5B-Instruct` revision in an isolated Python 3.12
  process. The model only selects a server-allowed explanation template and
  supplied evidence IDs. The main application does not import model libraries.
- `backend/cra_app/providers/evaluate_cases.py` evaluates three independent
  synthetic cases without sending their expected answers to the model. It
  reports provider and boundary results separately from clinical validation.
- CRA review, investigator/medical response and M06 links remain independently
  append-only. Linking creates only a selected `medical_clarification` Action
  and never completes it.
- `web/src/features/safety/AssessmentPanel.tsx` displays dimensions,
  candidate/unknown state, evidence, questions, timely alerts, provider
  rejection and separate CRA/medical forms. There is no global clinical-safe
  result or automatic Action completion.

## Remaining limits

- Only three independent synthetic cases and authored safety rules were used.
  No real protocol, IB, AESI list, DLT definition, safety database or clinical
  record was processed.
- The small local model did not perform clinical reasoning independently. It
  selected a constrained explanation template and supplied evidence IDs;
  deterministic code performed all dimension routing.
- Candidate means review material only. It is not investigator confirmation,
  an SAE/PD determination, a causality judgment or a reportability decision.
- Missing source facts, adopted reference-safety version, AESI/DLT definitions,
  awareness time or project deadline remain unknown. No deadline is inferred.
- No clinical accuracy, key-error threshold, representative hospital format,
  total manual effort or time-saving comparison has been established.
- A production model/image/mirror, concurrency/resource plan, approved data
  processing terms and real authorized trial remain for W15.
- OCR, reports, directory status, EDC write-back and real sending/signature are
  outside W09 and were not implemented.
