# Newspaper — 全球新闻双语日报

使用 GitHub Actions 自动收集前一日（北京时间 00:00–24:00）的新闻，在北京时间每天早上 07:00 尝试发送到指定邮箱。支持全球新闻、美股、美联储、创业、AI 科技、医疗科学。

## 运行模式

- 无需新闻平台 API Key，也无需 OpenAI/DeepSeek API Key。免费 RSS、可公开访问的新闻页面与 Argos Translate 离线英中翻译。
- 配置了多个候补来源；如果文章有付费墙、抓取失败、正文太短或无法确认发布日期，就跳过，优先选同一栏目其他来源。
- 每篇包含来源、发布时间、英文标题、中文标题、英文正文阅读选段、对应中文翻译、原文链接。不是仅转载 RSS 摘要；但为了版权与篇幅限制，也不宣称能全文复制所有商业媒体文章。
- 只收集北京时间前一个自然日的新闻。无新闻的栏目不填充旧新闻；某些日子文章不足则少发。
- GitHub Actions 的定时启动可能延迟，GitHub 和邮箱网络也可能影响实际到达时间；不是 07:00 正点投递保证。
- 仅私用阅读；不突破付费墙、登录和反爬访问限制。公开转载内容需另行核对版权和来源条款。

## 部署步骤

1. 将开发分支的 Pull Request 合并进入默认分支 main。GitHub 定时工作流只在默认分支运行。
2. 在用于发信的 QQ 邮箱网页设置中开启 SMTP，并生成【SMTP 授权码】，它不是 QQ 登录密码。收件邮箱可以与发件邮箱不同。
3. 打开仓库 Settings → Secrets and variables → Actions → New repository secret，依次设置：
   - NEWSPAPER_SMTP_FROM：发件 QQ 邮箱地址（如 example@qq.com）
   - NEWSPAPER_SMTP_PASSWORD：该发件 QQ 邮箱对应的 SMTP 授权码
   - NEWSPAPER_TO：日报收件邮箱地址
4. 进入仓库 Actions → Newspaper - Bilingual World News → Run workflow。默认 dry_run=true 仅生成虚构示例供检查，不发邮件。改为 dry_run=false 才会尝试抓取真实新闻并通过 SMTP 发送。
5. 查看运行日志，确认 RSS、正文抓取、翻译模型安装、邮件 SMTP 均通过。首次运行会下载离线翻译模型。

**安全提醒：不要在对话、仓库源代码、日志、Issues、PR 评论或公开文件中粘贴 SMTP 授权码。**

## 结构

- feeds.json：栏目标配额、北京时间、备用 RSS 来源、文章截选上限。
- reader.py：抓取公开可访问的新闻页面，提取正文并按段落取精选选段。
- digest.py：昨日日期过滤、日期与标题去重、跨来源选择、离线翻译和 HTML/TXT 邮件发送。
- requirements.txt：Python 包依赖。
- ../.github/workflows/newspaper.yml：23:00 UTC (= 北京次日 07:00) 定时任务。

## 维护与局限

1. GitHub 公开仓库定时任务可能因连续 60 天无仓库活动而被停用；定期检查 Actions。
2. 真实新闻的完整正文若不可读取，只会标记来源失败并寻找替代，不会凭空扩写。2200 字符上限为可阅读新闻选段，不是对商业原文的全文存储。
3. 机器翻译尤其在财报、药品名称、金融缩写方面可能出错，标题与英文保留供核对。
4. 新闻源有效性会变化。候补列表不是已逐一确认每天都可用的保证。
5. 对 07:00 分钟级时效要求很高时，需要改用更可靠的定时调度服务。

## 本地运行

python -m pip install -r newspaper/requirements.txt
python newspaper/digest.py --demo --output /tmp/newspaper-preview
python newspaper/digest.py --dry-run --output /tmp/newspaper-real-preview

模拟预览不发送邮件。真实预览需联网抓取文章和首次下载翻译模型。


## 新增：新闻总编辑排序（无大模型 API）

使用成熟开源项目 [scikit-learn](https://github.com/scikit-learn/scikit-learn) 的 TF-IDF 和余弦相似度对英文标题进行同一事件的相似报道聚合，然后进行透明评分。程序见 newspaper/ranking.py。

| 维度 | 权重上限 | 当前启发式指标 |
|---|---:|---|
| 事件影响 | 30 | 监管、宏观、企业经营、研究突破等高影响词汇 |
| 栏目匹配 | 25 | 投资、宏观、创业、科技、医疗、全球新闻的偏好配置 |
| 多媒体覆盖 | 20 | 不同媒体报道相似事件（不代表事实核验） |
| 新信息线索 | 15 | 新公布、批准、推出、数值等（并非严格新旧事实比对） |
| 时效性 | 10 | 昨日北京时间内发布时间 |

高评分报道优先进入候选池，同一事件保留不同媒体的候选版本；遇到打不开、付费墙、正文过短的报道优先选择可读取的替代版本。避免来源垄断。日报首页展示今日重点 5 条，每篇附参考评分和推荐理由。

注意：没有大模型时，规则难以准确判断事件的真正社会影响、辨别所有改写报道，也不能保证发现冷门但重要的新闻。分数不能解释为事实准确率、投资预测或人工审核结果。

## 新增：每篇文章末尾的英语学习区

采用 [spaCy](https://github.com/explosion/spaCy) 官方模型 en_core_web_sm 和可复核的语法规则，不需要外部 AI API。

- 本篇生词：从真实正文中提取确实出现的财经、创业、技术、医疗等主题词汇，每篇最多 5 个。
- 本篇语法：每篇最多 3 个，识别现在完成时、被动语态、条件从句、定语从句、情态动词、不定式、一般过去时等。
- 每条语法包含正文中的真实英文例句、离线中文翻译、结构和用法说明。匹配不足可少于 3 个，不会编造新闻中的语法例句。
- 词汇和语法均直接出现在该篇新闻下方，兼容 QQ HTML 邮件和纯文本邮件。
- 机器句法、专业术语及离线翻译均可能误判，学习时可核对英文原文。

依赖 scikit-learn 和 spaCy 的免费本地算法与开源模型，需要在 Actions 首次运行时从官方源下载安装，但不需要购买新闻或 LLM API。

## 回归测试

运行：python -m unittest discover -s newspaper -p 'test_*.py' -v

GitHub Actions 在 PR 测试期间不会发送真实邮件，会执行版式预览与日期、候补来源、评分、文章真实语法句、词汇位置等测试。

## V0.3 — 长文连贯阅读（基于阅读反馈）

**反馈**：上一轮样刊正文太短、上下文不足，读起来像剪切内容。根因是旧配置每篇最多 2,200 英文字符，并从文章开头、中段、结尾拼接不连续段落。

**已实现的改动**：

1. 保留原有 GitHub 源 [Trafilatura](https://github.com/adbar/trafilatura)，将正文提取从 favor_precision 调整为 favor_recall，以减少对真实正文的过度裁切。
2. 从导语起截取连续、完整段落。若长度上限已满，停止；不再转跳到文章中后部。不截断句子或段落。该算法仍是**原文选段**，不是 AI 改写。
3. 将最高正文选段长度设为 **6500 英文字符**，把可接受的最低正文设为 **1400 英文字符**；过短的段落不能达到最低质量要求，使用其他可抓取新闻替补。
4. 为适应长文阅读与 GitHub 免费 runner，将六类当天报道配额从 26 调整为最多 **14 篇**（全球 3、美股 3、美联储 2、创业 2、科技 2、医学 2）。优先保证信息密度，而不是凑够数量。
5. 邮件明确标注选段是否被截断及是否从文章导语连续截取，防止与完整全文或人工原创报道混淆。原有每篇词汇、真实语法句、北京时间日期、推荐评分、QQ SMTP 配置保留。

**仍未实现 / 不能误称的能力**：

- 不调用外部 AI API 的离线规则不能可靠地重新撰写“事件经过 → 背景 → 原因 → 数据 → 影响 → 接下来发生什么”的完整中文新闻分析，尤其无法保证多来源信息之间的逻辑关系。
- 因为版权和访问限制，不复制无法授权的商业媒体整篇文章；扩大选段不等于获得转载许可。实际部署前仍应核查各来源使用条件。
- 如果用户未来需要真正独立撰写的 800–1200 字原创中文深度报道，应增加经过质量/事实校验的本地生成模型或人工编辑工作流，不能仅靠正则和抓取拼接宣称已经实现。

回归测试：`python -m unittest discover -s newspaper -p 'test_*.py' -v`，重点校验连续段落、单句边界、正文过短自动淘汰和版式。
