# Newspaper — 全球新闻双语日报

**这是新闻日报，不是独立的内参系统。**

## 生产唯一权威入口

- [production_policy.json](production_policy.json)：**唯一机器可读生产合同**（时区、截稿、定时制作、发送窗口、来源与产品原则）。任何改变时刻的提交，必须同步修改 Python、工作流 cron、回归测试，并由 `verify_schedule.py` 校验一致性；禁止凭 README 里的旧时刻上线。
- [V2_IMPLEMENTATION.md](V2_IMPLEMENTATION.md)：详细需求、测试和验收标准。不得出现与上面 JSON 相矛盾的当前操作说明。
- [HISTORY_BEFORE_20261014.md](HISTORY_BEFORE_20261014.md)：旧版说明，仅供追溯，任何旧时间要求均已作废。

## 当前已确认的唯一生效时间

**北京时间凌晨 01:00 为正式邮件发送目标**。UTC cron 及北京时间的精确映射由 `production_policy.json` 和 `verify_schedule.py` 保证：

- 北京时间 **00:00**：锁定此前 24 小时新闻范围，为新闻采集、审校与 PDF 制作提供提前量。
- 北京时间 **00:05、00:20**：两轮准备尝试，生成带来源的 PDF 和独立邮件正文，SHA-256 完整性保护并缓存在跨 Actions 执行的准备缓存中。
- 北京时间 **01:03、01:16、01:29、01:42、01:55**：优先发送已准备的内容；未准备成功则在允许窗口内执行保底准备；当日有 SMTP 接受凭据就跳过。
- 北京时间 **02:00**：强制停止当日 SMTP 交接，防止旧日期混入次日。**不是 07:00，也不是 06:00。**

**重要边界：** GitHub Actions 的 cron 是尽力触发，非实时服务 SLA；仓库在线不等于计划必达。SMTP_ACCEPTED 不代表用户收件箱已收到；发送凭据是非事务性的尽力去重。独立的七日投递巡检已设置，用于发现问题，不代表自动补发。

## 编辑标准

采用重大新闻详尽、普通报道适度精简；美股与全球资本市场为头版，中国与美国合计常态三篇、世界政治及 AI 科技等独立栏目；重大新闻附来源约束的因果解读，期末另设《今日关键变化》。多源事件聚类与交叉验证，保持原文语气、重要数字和当事方立场；尊重来源版权。

## 一般安全约束

PR 和 `dry_run` 都不能读取正式 SMTP Secret。人工 `workflow_dispatch` 默认只预览。真实邮箱发信须经过北京时间 01:00–02:00 检查与每日凭据检查；无事实来源或 PDF 生成失败不发送空刊。整期模型费当前采用更严格的人民币 ¥1.00 事前上限，不因规范改时间而提升付费额度。
