# Newspaper — 全球新闻双语日报

**这是新闻日报，不是独立的内参系统。**

## 生产唯一权威入口

- [production_policy.json](production_policy.json)：**唯一机器可读生产合同**（时区、截稿、定时制作、发送窗口、来源与产品原则）。任何改变时刻的提交，必须同步修改 Python、工作流 cron、回归测试，并由 `verify_schedule.py` 校验一致性；禁止凭 README 里的旧时刻上线。
- [V2_IMPLEMENTATION.md](V2_IMPLEMENTATION.md)：详细需求、测试和验收标准。不得出现与上面 JSON 相矛盾的当前操作说明。
- [HISTORY_BEFORE_20261014.md](HISTORY_BEFORE_20261014.md)：旧版说明，仅供追溯，任何旧时间要求均已作废。

## 当前生产发送时序（以 V2.3 JSON 为准）

**北京时间 00:00 截稿，00:01 起尝试自动启动；PDF 校验完成即调用 QQ SMTP，不等待固定发送时刻。**

- **00:01、00:16、00:31、00:46、01:07、01:37、02:07、03:07、04:07**：GitHub 定时启动及同刊期恢复尝试。某次运行在任何时间完成有效 PDF，都立即进入邮件交接。
- **当日恢复与防重复**：同一北京时间日期仅允许一个已记录的 SMTP 接受回执；其它触发优先查询回执，避免重复发信。次日不补发旧刊。
- **验收边界**：`SMTP_ACCEPTED` 表示 QQ SMTP 服务器接受，不等于最终进入 QQ 收件箱；应通过 QQ 邮箱收件情况继续判断。

GitHub Actions `schedule` 为尽力调度，不保证在 00:01 准时执行；2026-10-15 日报曾在 07:26 收到 QQ SMTP 接受确认，该次成功运行并不足以证明自动定时可靠。详情参见 [P0 事故审计](P0_TRIGGER_AUDIT_2026-10-15.md)。

## 独立备援

当前没有独立于 GitHub Actions 的真实启动保障；多条 GitHub cron 可以提供迟到恢复机会，但不能消除 GitHub 平台整体延迟。

## 编辑标准

采用重大新闻详尽、普通报道适度精简；美股与全球资本市场为头版，中国与美国合计常态三篇、世界政治及 AI 科技等独立栏目；重大新闻附来源约束的因果解读，期末另设《今日关键变化》。多源事件聚类与交叉验证，保持原文语气、重要数字和当事方立场；尊重来源版权。

## 一般安全约束

PR 和 `dry_run` 都不能读取正式 SMTP Secret。人工 `workflow_dispatch` 默认只预览。真实邮箱发信须经过当日刊期检查与每日凭据检查；无事实来源或 PDF 生成失败不发送空刊。整期模型费当前采用更严格的人民币 ¥1.00 事前上限，不因规范改时间而提升付费额度。
