# Newspaper — 个人双语报纸

**正式编辑日报：供决策者阅读的来源忠实完整报道，保留英中逐句对照。**


## 2026-10-13 最终确认的正式内容标准

**本部分优先于早期V0.5/V0.8原文剪报规范。**

- **中美合并栏目**：政策、政治、经济、突发等均可入选；目标共3篇，尽量两国都有覆盖，不机械指定1:2，也不能在其他栏目重复刊登。
- **国际政治与全球事件**：至少3篇（满足来源质量时）；重大突发可扩充。其他领域依次为金融、宏观与美股；AI与数字产业；科技、能源与前沿科学；创业、商业与企业竞争；医疗、生命科学与公共健康。
- **约13–16篇**：依质量弹性变化，重大事件可增篇；不为了填满栏目而把普通融资、宣传稿和次要新闻硬塞进来。
- **三条选稿规则**：同一事件去重合并；某国家的国际新闻过度集中则触发复核，重要新闻不得仅为地域均衡而被删除；中美关键素材缺失时主动补找并如实记录覆盖缺口。
- **完整编辑报道**：普通入选事件中文约500–800字，复杂重大事件约900–1300字，极重大事件可更长。英文同样是来源忠实的编辑稿，必须与中文对应；若是机器编辑稿，不能标为记者原文。引用原文仍需另行准确标识。
- **重要事实不可损失**：导语说明真实进展，保留数字、限定条件、背景、当事各方回应和明确分歧，列出已知影响与后续可核实节点；不自行编造因果和主观判断。
- **事实强度与归属**：考虑、提议、批准、实施不能互换；可能与确定不能混淆，不能把报道者推测改写为事实；所有重要编辑断言必须能追溯回当期来源段落。
- **安全退化**：来源缺失、模型超预算或来源对照校验不通过，则保守保留原段落，明确标记，不生成短摘要或虚构内容。
- **分工边界**：新闻PDF写事实与来源，邮件中的DeepSeek评论独立给出有条件的分析；每周战略内参属于下一阶段，不混入本次日报整改。

## 早期 V0.8 兼容说明

- **英文新闻来自网页正文提取**（Trafilatura + spaCy 分句），不是大模型用自己的语言重写。最多读取每篇前约 18,000 英文字符；网页不可访问或原文较短，则无法保证整篇。标题、记者姓名、原句保持来源内容。
- 允许适度删节，但仅在原文存在明显低价值段落时删除完整段落，**不生成连接句，不改写引语**，至少保留已取得原文的 70%（比用户要求的三分之二更严格）；完整网页提取前已经截断的部分不算在这个百分比里。
- **全球政治/国际**默认 4 篇，优先至少含 **1 篇中国、1 篇美国、另 1 篇其他重大政治事件**；最多额外加入两篇具有足够重要性评分的报道。如果当天实际无法取得满足条件的可读原文，日志必须说明短缺，禁止编造。
- **AI 与科技**只选实质研究/科技进展：AI 能力、科学发现、核聚变、量子、材料、半导体、机器人等。排除电视剧预告、电影、影视娱乐活动、明星新闻。
- 每篇英文原句紧跟中文翻译，PDF 阅读版不显示原网页链接；PDF 保留已获用户认可的 A5 版式。
- 邮件评论由 `GLOBAL_STRATEGY_EDITOR.skill.md` 约束：形成因果机制、二阶影响、反面论点、主要不确定性，避免逐条摘要和模板套话。优先使用更强的 `deepseek-v4-pro`，但**只有事前按实际峰谷价格估算不超过 ¥0.18 才选用**；否则预先选择 `deepseek-flash`，一封邮件最多一次 AI 请求，不自动重试。单次目标上限 ¥0.20，最多 3400 输出 tokens。
- 中文仍以 Argos 离线机器翻译为基础，新增 `translation_editor.py` 修正常见技术术语、检查否定丢失/百分比和错位问题。**这不是完整的人类编辑翻译**；需要高水平逐句翻译时，未来还需更好的本地模型或单独评估质量/费用的云模型。不可假称已完成。

**工程规范**：`JOURNALIST_EXTRACTIVE_EDITOR.skill.md` 和 `GLOBAL_STRATEGY_EDITOR.skill.md`。新闻原文仍在 PDF，AI 全球评论只在邮件正文。所有工程更改和测试仅在 GitHub；不要求用户本地安装。

## 每日输出

- 北京时间每日01:00截稿之前24小时（前一日01:00至当日01:00，左闭右开）的精选报道；BBC World、The Guardian、CNBC、TechCrunch、Y Combinator 等为候选来源。RSS 抓取/正文识别失败或无法公开阅读时，自动选择其他候选报道，不伪造原文。
- 报纸 PDF 采用用户已认可的 A5 竖版、衬线英文字体、中文宋体风格。每个领域下面排列媒体、作者、英文原标题、中文标题及正文。
- **原记者的英文句子在上，对应中文翻译立即在下一行**；连贯顺序和段落保留。长文在最大 18,000 英文字符以内尽量收录可提取的全部正文，遇到截断明确注明是连续选段。
- 不再把报道缩成标题 + “据媒体报道” + 空洞机制解释；不放编者导语、顾问观察、事实材料、正文英语附录，也不显示原文网页链接。
- 每篇最多三处语法数字标注，解释在紧随正文的位置，不复制大段原句。
- **邮件正文**独立由 DeepSeek 基于当天入选文章生成中文全球形势评论；不让 DeepSeek 修改 PDF 的记者英文原句。

## 费用及安全

- QQ SMTP：`NEWSPAPER_SMTP_FROM`、`NEWSPAPER_SMTP_PASSWORD`、`NEWSPAPER_TO`。
- DeepSeek：`NEWSPAPER_LLM_API_KEY`；预算许可时优先 `deepseek-v4-pro`，否则 `deepseek-flash`；每次正式工作流最多一次请求，无自动重试，`max_tokens=3400`。
- 单次 AI 预算最高人民币 ¥0.20，内部执行预警线 ¥0.18。按照**请求发生的北京时间**判断：周一至周五 09:00–12:00、14:00–18:00 采用高峰价格，其余采用官方低谷价格。中国法定假日保守按普通工作日分类，以避免低估成本。费用估算基于全部缓存未命中的输入及允许的最大输出 tokens。
- 当前报价：Flash 高峰输入 ¥2/百万 tokens、输出 ¥8/百万 tokens；低谷输入 ¥1/百万 tokens、输出 ¥4/百万 tokens。程序在 GitHub 上预估费用，若超出 ¥0.18 则不发出请求。最终结算仍以 DeepSeek 实际收费为准，服务商可能调价。
- API Key 和 QQ 授权码只在 `main` 分支正式发送步骤注入；PR、模拟预览、真实数据 dry-run 全部不调用付费 API 或读取密钥。

## GitHub 操作

1. 打开 [Newspaper Actions](https://github.com/pyzz58/gpt-recommendations/actions/workflows/newspaper.yml)。
2. 主分支 `main`，`dry_run=true` / `preview_kind=live`：只生成真实素材的 PDF、HTML 和 TXT 预览，不发信。
3. 主分支 `main`，`dry_run=false`：抓取真实新闻、生成 PDF、调用最多一次 AI 评论并投递 QQ 邮箱。
4. 每天北京时间凌晨 **01:00** 触发生成并发送；**01:15、01:30、01:40** 补偿触发。每期固定覆盖前一日01:00（含）至当日01:00（不含），即使 GitHub 任务延迟启动也不移动截稿边界。
5. 生产发送步骤只允许在北京时间 **01:00–01:57** 发起，02:00以后禁止补发当期过期新闻。QQ SMTP 投递开始前预留约3分钟，但网络和 GitHub 平台行为仍不提供硬性“02:00之前送达收件箱”保证。
6. 同一天成功发送后，通过 GitHub Actions cache 记录收件凭据，后续补偿触发会跳过生成和重复发送。此机制属于尽力去重，不能替代邮件提供商的最终送达回执。
7. GitHub 的定时触发本身不是严格 SLA；若全部触发被延迟/跳过，系统不会凭空自动补发。需要严格时限与失效告警时应部署独立调度器/外部监控。失败可在 Actions 日志查看具体阶段。

新闻源版权、传播和使用限制应由来源提供方的规则及适用要求另行确认；程序不能突破登录或付费墙，也不能把来源无法获得的文章伪装成完整报道。
