# Newspaper — 全球新闻双语日报

**这是新闻日报，不是独立的内参系统。**

## 生产唯一权威入口

- [production_policy.json](production_policy.json)：**唯一机器可读生产合同**（时区、截稿、定时制作、发送窗口、来源与产品原则）。任何改变时刻的提交，必须同步修改 Python、工作流 cron、回归测试，并由 `verify_schedule.py` 校验一致性；禁止凭 README 里的旧时刻上线。
- [V2_IMPLEMENTATION.md](V2_IMPLEMENTATION.md)：详细需求、测试和验收标准。不得出现与上面 JSON 相矛盾的当前操作说明。
- [HISTORY_BEFORE_20261014.md](HISTORY_BEFORE_20261014.md)：旧版说明，仅供追溯，任何旧时间要求均已作废。

## 当前生产发送时序（以 V2.2 JSON 为准）

**北京时间 00:00 截稿，01:00 是 QQ SMTP 最早允许交接的时间，不保证 GitHub 在这一分钟准确触发。**

- **00:01、00:16、00:31、00:46**：GitHub 定时尝试启动；若实际开始时仍未到 01:00，则只制作带哈希清单的当天 PDF 邮件包并缓存，不能提前发送。
- **01:07、01:37、02:07、03:07、04:07**：安排同刊期的发送及恢复尝试。如果 GitHub 把原定 00:xx 的事件延迟到 01:00 后，系统也可按实际运行时间进入发送阶段。
- **01:00–当日 23:59**：若报纸内容准备完成，允许当天迟到补发；不能在 01:00 前发信、不能次日补发旧刊。每期使用每日发送回执避免重复投递。
- **验收边界**：`NEWSPAPER_DELIVERY_STATUS=PREPARED_NOT_SENT` 仅为备稿；`SMTP_ACCEPTED` 表示 QQ 发信服务器接受，不等于 QQ 收件箱确认。送达仍须用户在 QQ 邮箱核实。

GitHub Actions `schedule` 是尽力调度。2026-10-15 的真实定时记录曾延迟至凌晨 04:xx 才出现；当天 07:26 的 QQ SMTP 接受发生于一次专门的 `push` 检验，而非准时 schedule。证据及各运行 ID 见 [P0 事故审计](P0_TRIGGER_AUDIT_2026-10-15.md)。

**独立备援仍未完成**：如要降低 GitHub cron 漏触发的风险，需要获得经授权的外部独立定时源，通过已有的 `workflow_dispatch` 接口在北京时间 01:00 后触发。不能以仓库内另一条 `schedule` 代替真正独立备援。

## 编辑标准

采用重大新闻详尽、普通报道适度精简；美股与全球资本市场为头版，中国与美国合计常态三篇、世界政治及 AI 科技等独立栏目；重大新闻附来源约束的因果解读，期末另设《今日关键变化》。多源事件聚类与交叉验证，保持原文语气、重要数字和当事方立场；尊重来源版权。

## 一般安全约束

PR 和 `dry_run` 都不能读取正式 SMTP Secret。人工 `workflow_dispatch` 默认只预览。真实邮箱发信须经过北京时间 01:00 起、同日内的刊期检查与每日凭据检查；无事实来源或 PDF 生成失败不发送空刊。整期模型费当前采用更严格的人民币 ¥1.00 事前上限，不因规范改时间而提升付费额度。
