# Newspaper — V0.9 全球新闻编辑日报

本版落实2026-10-13用户确认的栏目、事件选稿、长篇编辑报道与投递整改；不提前加入家族内刊、长期投资判断或周刊功能。

## 栏目与版面

- 中国与美国合计3篇，涵盖政策、经济、政治、社会与突发事件；通常兼顾两国，不机械分配2+1。
- 国际政治与全球事件3篇；金融、宏观与美股3篇；AI与数字产业2篇；科技与前沿科学1篇；全球商业与创业前沿2篇；能源、资源与供应链1篇；医疗与生命科学1篇。上限16篇，短缺如实披露，不用低价值报道填满。
- 所有来源先做跨栏事件聚合，同一事件只入选一次。中美未入选的不同事件仍可按主题进入其他栏目。
- 来源多样性按媒体主体计算，BBC的多个RSS不是多家媒体。国际栏目同一非中美国家第二篇必须达到重大事件阈值，并记录集中度复核标记。国家判断目前是标题实体启发式，不是完美的地理识别。
- 评分为跨国影响30、规模25、结构变化20、新进展15、媒体广度10的透明启发式。保存各项信号，绝不称为事实核验、精确影响测量或成熟商业机构的专有算法。
- 增加商业、经济、能源、美国政治及中国补充来源。中美候选在正文获取之前预留位置；来源无法读取时换同事件其他来源，再选择其他合格事件。短缺在邮件披露。

## 完整编辑报道

目标是具备关键进展、必要背景、数字、相关方观点、限制与下一节点的可独立阅读报道，而非全文搬运或标题摘要。

- 一般目标350–550英文词；中文长度由实际翻译决定，不声称严格达到某个汉字数。较短来源不编造扩写；复杂限制条件必须保留时允许加长。
- 本阶段采用**完整段落编辑**：优先去掉重复和枝节，保留来源原句、观点归属和先后顺序。不是自由改写、多源原创调查或已经具备人类编辑水平的综合报道。
- AI只输出来源段落编号，不能把生成的新事实句写入PDF。导语、否定、条件、争议和不确定性受到程序保护；无效编号拒绝使用。保留源文、段落编号、内容哈希和入选依据，支持回查。
- AI选段和独立邮件评论合并成一次请求，维持每期最多一次付费请求、3400输出tokens、预估¥0.18/上限¥0.20。调用之前持久登记，断点恢复不会再次付费。材料超预算、模型不可用或输出不合格时，使用保守段落编辑；邮件明确说明评论未生成。
- PDF英中逐句对照和语法批注保留，仍使用现有Argos离线翻译与术语/否定检查。这不是人类译审，不能保证杜绝翻译错误。
- 新闻事实与邮件评论分离。评论中的事实须注明媒体；正文不把“考虑”写成“实施”，不把预测写成已发生事实。

## 投递与恢复

正式投递仍使用现有QQ SMTP及收件人Secret，不更换邮箱。

1. 北京时间06:37触发制作，准备完成后等待07:00发送。GitHub调度不保证准点；延迟启动则在完成后补发。
2. 07:07、07:20、08:20、09:20补偿触发；共享并发锁，并在安装依赖前检查当天状态。
3. PDF、邮件正文及编辑审计写入同日期Actions缓存，再发送。重试恢复既有成品，不重新翻译/调用模型。缓存丢失可以重建；当天AI请求已登记则不重复付费。
4. 持久投递台账位于独立`newspaper-delivery-state`分支的`receipts/YYYY-MM-DD.json`，只保存状态、时间、哈希和用量，不保存地址、密钥、新闻正文。
5. SMTP发送前登记`sending`，服务器接受后登记`accepted`。只重试确定在发送事务前的连接失败（最多3次）；认证或明确拒绝保留可诊断失败。发送后结果不明标记`uncertain`，暂停自动重发等待核对。
6. 退出SMTP连接失败不能把已接受的邮件判为失败。`accepted`只代表SMTP服务器接受，不代表进入收件箱。
7. 独立检查任务读取台账和Actions运行情况；未发送且无正在执行的日报时，更新`RECOVERY_REQUEST.json`并以`[newspaper-recover]`提交触发补偿。该任务必须实际启用后才算上线，不能仅凭代码宣称存在。

生产步骤使用GitHub临时token写投递台账；SMTP密钥只进入默认分支发送步骤，AI密钥只进入默认分支制作步骤。PR和手动dry-run不读取这些密钥，不发邮件、不调用付费API。

## 验证与运维

所有线上验证由GitHub Actions运行：

- 单元回归涵盖中美三篇、跨栏同事件去重、来源主体归并、地域集中度、正文限制条件、费用边界和SMTP故障。
- PR生成真实来源的无密钥PDF预览，作为真实采集与排版检查，不等于生产邮件端到端验收。
- `workflow_dispatch`: `dry_run=true`生成预览；`dry_run=false`按当天台账生成/发送，不会绕过已发送或不确定状态。
- 查日志时区分：未触发、制作失败、已准备、明确SMTP拒绝、结果不确定、服务器接受。不能把“工作流绿色”直接解释为收件箱已收到。
- 依赖直接版本固定在本项目成功投递时已验证的版本。外部网站改版、翻译模型下载、调度平台和邮箱服务仍属外部依赖；不能承诺绝对零故障。
