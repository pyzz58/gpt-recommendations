# Newspaper V0.5 —《全球形势秘书简报》产品与版式规范

**状态**：实施基准（2026-10-12）。所有实现与测试仅在 `pyzz58/gpt-recommendations` 的 GitHub 分支及 Actions 内执行；不要求用户配置本地环境。

## 1. 产品定位

目标是一份可下载、可收藏、适合手机阅读的**全球形势分析日报**。不是 RSS 原文复印机、英语教材或假装具备自主验证能力的“专家 AI”。

- 主输出：**排版精致的 PDF 附件**；网页风格 HTML 同时作为 GitHub Actions artifact。
- 邮件正文：简短投递说明、日期、主要观察领域、PDF 已附；不要在邮件正文中再次复制几十屏新闻。
- 观察窗口：北京时间前一日 00:00–23:59 已发布的新闻（提供发布时间）；核实来源，不能把前瞻当成已发生的结果。
- 覆盖：国际政治/安全、美股、宏观/美联储、创业、AI/科技、医疗/科学；不为凑数造新闻。
- 顾问正文全中文，以证据与条件性解释为主。英语学习只在文末附录，保留“英文一句、下一行对应中文一句”的严格格式。

## 2. 一期内容的标准顺序

1. 封面：期号、日期、主标题、范围、制作性质标识（“公开报道自动整理·非独立事实核验”）。
2. 编者导语：说明覆盖范围、主要议题以及风险，**不做 TOP5 或速览榜单**。
3. 各领域章节：正文仅包含中文顾问型文字。每个事件包含“事件与来源、背景和机制、可能影响、证据边界/后续指标”，而不是“英文标题/事实材料/顾问观察”框。
4. 末章：跨领域条件传导，标注仅为待验证的情景关系。
5. 附录：选取来源于正文的短英文原句（不超过每来源一短句），严格**英文一行、对应中文下一行**，不穿插栏目教学标签；高亮最多三处可靠的语法表达，标上标 `1` / `2` / `3`；紧接简短编号解释，**不再次复制整段原文**。
6. 来源脚注：媒体、北京时间发表时刻、原文章链接；不能以“多家媒体”之名隐去出处。

## 3. 编辑规范及事实边界

- **不要把原文机器翻译伪称原创评论**。事实依据可以来自已提取的公开报道，但评论必须与证据呈现分开。
- 不得将价格、预测、尚未完成的交易或相关性直接写成已发生的事实或因果证明。
- 单来源的敏感声明必须注明未交叉核验；发生和发表的时间不同必须区别。
- 未设立 LLM/人工编辑流程前，正文的观点属于**规则化观察框架**，不能声称是 GPT Researcher、STORM、CrewAI 生成的原创深度分析。若素材不足，应减少篇幅、写出“证据不足”，而非堆砌套话。
- HTML/PDF 中引用原始报道的短句数量从严控制；不复制整篇受版权保护原文。
- 不出现虚构的经济指标、统计、引用原句、事件进展或发布日期。
- 留出升级空间，但 V0.5 暂不实现“跨日研究记忆、专家团队 Agent、自动预测与自我反思”。

## 4. 视觉设计——严肃报刊 × 中文政经研究简报

不直接使用 BBC Reith 或其他媒体专有字体文件；采用兼容发行的公开字体体系：

- 中文正文：**Noto Serif CJK SC（思源宋体 / Noto Serif 家族）**；章标题中文可用 **Noto Sans CJK SC**。
- 英文标题/附录：Liberation Serif（Georgia 气质的兼容后备），标签使用 Liberation Sans。
- 页幅：**A5 竖版、单栏**（更适合手机阅读）；打印可自行缩放为 A4。
- 版心：左右约 13–15mm；顶/底边距约 17–20mm；中文正文约 10.5–11pt；行距 1.65–1.75。
- 调性：暖白纸色、深墨黑标题、少量酒红色强调、细横线分割；不要大面积蓝灰卡片。
- 一级标题固定视觉层级，段间距适度，避免孤行。页脚出现期号/页码；链接可以点击。
- 附录英文表达仅针对**真实出现在选句中的词组**进行加深+下划线+上标 [n]；编号解释简洁，一条不超过两句话。

## 5. 交付与安全

- GitHub Actions 运行时生成 `global-briefing-YYYY-MM-DD.pdf`，只在 runner 临时目录存放，作为邮件附件投递；同时生成 HTML 预览和 PDF artifact（便于回溯排版）。
- SMTP 授权码只注入发送步骤，其他 PR / dry-run / PDF 测试步骤不能读取。
- `--demo` 只用标明 DEMO 的样本生成 PDF，不得邮件发送；`--dry-run` 真新闻生成预览，不得发邮件；正式任务再 SMTP 投递。
- 正式发送前执行 CI、中文/英文字体可见性、PDF 能否正常生成与解析、英语双语相邻及语法标注测试。
- 当 PDF 生成失败时**不得**邮件发送“已附 PDF”的误导性邮件。记录故障并让工作流失败。
- GitHub schedule 在北京时间 07:00 **尝试触发**，不能保证分钟级到达。

## 6. 本次验收标准

| 指标 | 标准 |
|---|---|
| 用户阅读体验 | 打开 PDF 直接看到报刊封面与中文顾问正文 |
| PDF 文件 | 含可搜索中文文本，页面无乱码；邮件应含实际附件 |
| 内容性质 | 中文分析主体，来源准确、注明为规则型观察 |
| 文案清理 | 不出现“英文标题”“事实材料”“Grammar Focus”工具化章节标签 |
| 双语 | 附录严格英文行→相邻中文行，不合并、不留空行 |
| 语法 | 上标数字关联真实词组；篇末简洁释义、无重复整句 |
| 安全 | PR 和 dry-run 不注入 SMTP Secrets |
| GitHub | 全部源代码、规范、测试均在仓库；不使用用户本地电脑 |
| 发件 | 用户现有三个 `NEWSPAPER_*` Secrets，SMTP SSL 发件；要有成功/失败实测 |

## 7. 容许的现实差距

**将 HTML 邮件改成 PDF 并不会自动提升研究智力。** 为避免继续收到“小儿科”的伪评论，规则生成模式优先限制论断、保留出处并减少无数据空泛模板。若用户之后要求真正的多源专业评论，需单独引入经授权的强模型/人工审稿与断言级验证，再重新评估质量。当前不擅自假设可用 API、模型额度或秘钥。
