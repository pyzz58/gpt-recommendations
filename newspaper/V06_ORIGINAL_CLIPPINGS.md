# Newspaper V0.6 — 原文剪报规范（纠正 V0.5）

## 用户明确要求

这是**优秀人类记者报道的原文选编**，不是 AI 自己概述事件。选稿、去重、分类和报刊排版可以自动完成，但不得把原文改写成一句两句“据某媒体报道”的敷衍材料；原句按新闻作者原顺序排放，下一行逐句中文对译，并且就地用下划线/数字脚注讲解语法。

继续使用 V0.5 用户已认可的 A5 中文宋体风格、留白与 PDF 格式；PDF 不出现空洞的“编者导语”“事实材料”“顾问观察”“后续应核对”等模板。英语不是文末碎句附录，而是**每篇报道的正文**。评论员真正的每日大局研判应在**邮件正文**，不应污染记者原稿；无合适的推理模型或编辑时不可用规则伪装专业分析。

## 关于版权（必须明确）

可在线阅读、可被程序抓取，不等于已获授权将完整商业媒体报道重新汇编和翻译出版。

- 有**明确再版与中文翻译许可**的原文，按原顺序展示可取得内容。采集不完整时不能声称全文。
- 没有许可的 BBC、Reuters、Guardian 等来源：以最多 25 个英文单词的连续短原句摘录与**原文直达链接**呈现，并标清未获整篇重印授权。不跳段、不填入 AI 改写段落，也不将短摘标为整篇新闻。
- 完整英文报道和中文译文如果来自用户依法取得的授权材料、公共领域或合规开放许可内容，需要核对权利条件，特别是*翻译*是否获准。
- 授权目录在 newspaper/feeds.json 的 republication_licenses 字段；目前默认为空。仅拥有代码或 GitHub 项目的开源许可证，不等于拥有新闻作者的著作权。

因此，在取得商业媒体的再版许可之前，**当前不能做到把 Reuters/BBC 每篇完整稿件直接放进每日 PDF**。没有可信方法靠某个 GitHub 项目绕过这一限制。

## V0.6 技术实现

- clippings.py 直接渲染每篇报道的 original bilingual_pairs：英文一行→其译文下一行，保持作者原句与顺序。
- 内容模式：授权来源可全文（若提取器截断则标选段），其他来源为短原文摘录加可点击原媒体链接。
- 保留每篇原标题、中文标题、媒体、北京时间；注释仅讲原文中确实存在的标记表达，不重复整段英语。
- 邮件正文仅提供真实交付信息；不把“能源会影响通胀”等机械模板当作评论员观点。
- 可复用现有 RSS、Trafilatura、spaCy、Argos Translate、WeasyPrint，无本地工作或新的付费 API。
- 正文无人工生成的新闻摘要，自动化 CI 需验证无假文章、无碎片拼接、双语对齐、许可边界、PDF 可搜索和 SMTP Secrets 安全隔离。

## 相关成熟项目

- Readeck：https://codeberg.org/readeck/readeck — 个人保存、收藏原始可读文章，支持 EPUB。代码开放不等于媒体全文转载许可。
- FreshRSS：https://github.com/FreshRSS/FreshRSS — 订阅管理、RSS 内容聚合、API 和扩展；扩展生态含正文抓取。
- FreshRSS extensions：https://github.com/FreshRSS/Extensions — 文章正文抓取/翻译扩展，可借鉴工程路线。
- Stanford STORM：https://github.com/stanford-oval/storm — 多视角研究和有来源的长篇写作系统，需要 LLM。更接近评论员分析；不是无 API 的免费即插即用工具。

目前先修复内容与排版，不擅自增加连续研究或假称深度评论；在获得可合法再版原文和研究模型后再拓展。
