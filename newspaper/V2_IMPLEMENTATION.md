# 新闻日报 V2.0 — 正式生产实施规范及验收记录

> 范围：仅 `newspaper/` 及 `.github/workflows/newspaper.yml`。
> **内参、股票分析、导演及其他项目与此系统独立，严禁交叉修改。**
> 版本：2026-10-14。部署前本页应与默认分支代码、实际 GitHub Actions 运行记录对照。

## 经用户确认的产品合同

- 内容深度：重大新闻完整深入，普通新闻适度精简，关键事实与来源不可丢失。
- 分析位置：重大新闻附事实明确的专业解释，整期末尾《今日关键变化》；避免通篇机械汇总。
- 美股头版：指数/收益率仅为辅助市场快照；主要关注财报、政策、监管、经济数据、机构发布及市场重大事件，所有市场数值标注交易日期及来源。
- 中国与美国独立栏目常态三篇，另设国际事件、AI 科技、商业创业、经济社会等；同一重大事件去重，重要事件不受固定篇数阻碍。
- DeepSeek 全期成本不得超过 **1 美元**。当前已有更严格的 **人民币 ¥1.00 事前预留上限**，本 PR 不扩大支付权限。未来如需扩大到美元上限，必须增加币种折算核验及用量数据证据。
- 第三方新闻保留来源链接、准确归属与合法引用，不默认复制版权原文。

## 当前生产合同（替代所有旧的 01:00/02:30 时间规则）

- 新闻窗口：**北京时间前一日 06:00（含）至当日 06:00（不含）**。
- 制作：北京时间 **06:05、06:20** 启动准备，内容合格后生成不可变的 PDF、邮件 HTML/TXT 与 SHA-256 摘要文件，并放入每日 GitHub Actions cache。
- 发送：北京时间 **07:01、07:17、07:31、07:47** 触发检查。如果当日已发送则跳过；若已有准备好的版本，不再抓取新闻、不安装大模型依赖，直接交给 SMTP；若准备任务未执行，允许在发送窗口内重新制作作为保底。
- 最晚时间：在 **07:00（含）至 08:00（不含）** 的北京时间内可进行 SMTP 交接；过期报告必须拒绝发送，不能默默错发。
- `dry_run=true` 的 `workflow_dispatch` 和所有 PR 均不会读取 SMTP 凭据，不会真正发信。
- `dry_run=false` 仅用于明确授权的人工手动发送；也必须遵守上述日期、时窗、缓存/收件人约束。
- 不再保留历史的一次性 push 标记触发、过期的 10 月 14 日补发特例等正式生产入口。
- GitHub Actions `schedule` 并非实时 SLA；多 cron 只是缓解，不能保证绝不遗漏。**真正独立的外部 watchdog 仍然未部署**，需要独立执行环境与独立故障告警渠道。

## 最小架构

```text
公开新闻/RSS -> 事实与选题 -> 编辑/翻译/分析 -> PDF+邮件内容
  06:05/06:20  --prepare -> /tmp/newspaper-ready (哈希+版期校验)
  GitHub Actions cache: newspaper-ready-v2-YYYY-MM-DD
  07:01/07:17/07:31/07:47 -> read & verify -> SMTP accepted
  GitHub Actions cache: newspaper-sent-YYYY-MM-DD
```

发送阶段仅运行 Python 标准库 `prepared_delivery.py`。必须完成 bundle 的日期、主题、哈希、PDF 文件头校验，再执行 QQ SMTP。SMTP 返回无拒收者只说明**服务端接受交接**；并不等于收件箱已收到。日报状态应明确区分 `PREPARED_NOT_SENT`、`ALREADY_SENT`、`SMTP_ACCEPTED`、`SMTP_ACCEPTED_RECEIPT_UNVERIFIED` 与 `FAILED`。

## P1 编辑质量验收

- 每个启用来源测实际可达、发布日期、发布时间窗、HTML 提取成功率；36氪、新华网、人民日报海外版、雪球不得以配置存在当作实际入选。
- 同事件多来源合并，不把实质性新进展误删。
- 用 30–50 条历史重大事件建立漏选率/错选率基准。
- 美股头版：数据来源、日期、市场是否开盘、监管原始资料及机构观点来源可溯。
- 新闻正文：重大事件 5W1H、背景、核心数值、当事方回应、已知后果及不确定性。
- 中文翻译不能改变原文的肯定/否定、推测力度、关键日期与数字。
- 重大新闻分析标注事实/推论，《今日关键变化》不机械重复日常新闻。
- 邮件/PDF 在真实邮箱与移动端抽检版式、附件、链接及可读性。

## P2 费用与稳定验收

- 实际每天记录模型调用次数、输入/输出 tokens、保守成本上界。
- 超预算降级不允许捏造新闻或发送空 PDF。
- 测试新闻源、模型、PDF 生成、邮件服务器及缓存任一层失败时的结果，不得静默视为成功。
- 独立于 GitHub Actions 的健康检查器需要独立环境；部署前不可宣称已具备该保障。

**禁止声称全部完成：只有 CI、实际 scheduled run 与收件箱验证的具体运行记录齐备，才可将对应 NOT RUN/PENDING 升为 PASS。**
