# 新闻日报 — V2.4 实施与验收（仅新闻日报）

本文件说明执行和验收，不再独立定义旧版定时规则。生产唯一权威配置为 [production_policy.json](production_policy.json)；正式工作流为 [newspaper.yml](../.github/workflows/newspaper.yml)。旧版规则、旧探针、临时补测均作废；内参是完全独立的系统。

## 一、唯一时间合同

- **北京时间 00:00 截稿**：报道范围为前一日 00:00（含）至当日 00:00（不含）。
- **北京时间 00:01 唯一自动启动请求**：UTC 前一日 16:01，唯一 cron 为 `1 16 * * *`。
- **没有固定完成时刻或最早 01:00 才能发送的门槛**：一旦 PDF、HTML、TXT 与哈希清单校验通过，即立即向 QQ SMTP 交接。
- 只保留同日刊期和 00:01 最早交接校验、每天的 SMTP 接受回执防重复发送。
- GitHub Actions schedule 并不提供准时或必定触发承诺；真实未触发没有可执行的 job，必须如实报告。

## 二、编辑产品合同

- **内容长度**：重要复杂新闻深度报道，普通新闻适度精简；关键事实、数字、人物、时间、背景、争议与后续节点不可丢失，禁止机械摘要化。
- **重大新闻分析**：事实与推论清晰区隔；当日核心变化、因果链、影响路径、反例与可验证变量。
- **整期观察**：末尾《今日关键变化》，围绕 1–3 条关键结构性变化论证，不逐条复述新闻标题。
- **头版**：美股与全球资本市场，包括核心指数快照及日期、Fed/SEC/官方经济统计、重大业绩和机构分析；不能把实时指数仪表盘当成新闻正文。
- **全球覆盖**：中国与美国栏目常态合计 3 篇，国际政治、AI 与科技、产业、创业商业、医疗生命科学等保留，重大事件不受配额阻碍。
- **新闻价值**：必须是真实、重要、有社会/政治/经济/科技影响的新事实或进展；同事件多来源合并但不可误删后续重大进展，反娱乐八卦与宣传软文。
- **来源/版权**：每条可追踪到真实原始来源；机器翻译不改变语气、数字、时间。第三方版权正文不得默认全文转载。
- **预算**：目前已部署 `EditionBudget` 保留更严格 **人民币 1.00 元/期上限**；用户批准的最高容许是 1 美元/期，但在实际汇率换算及账单证据完成前，不扩大生产授权。


## 三、流水线及状态

```text
单一 GitHub schedule 事件 (00:01 BJT 计划)
   -> 当前日期校验 -> 当日回执查询 -> 新闻采集/选题/撰写
   -> PDF + HTML + TXT + SHA-256 清单验证
   -> 立即 QQ SMTP -> 记录已接受回执和运行证据
```

- `SMTP_ACCEPTED`：SMTP 服务器接受，不能视为 QQ 收件箱送达。
- `ALREADY_SENT`：当日 SMTP 接受回执已存在，因此本次没有重复发送。
- `SMTP_ACCEPTED_RECEIPT_UNVERIFIED`：SMTP 已接受但回执保存失败，应人工排查而不是盲目自动重发。
- `FAILED`：无法确认成功发送，必须由日志解释发生在哪一层。
- GitHub Actions 缓存回执为尽力去重，并不提供事务级 exactly-once 保证。

## 四、客观验收标准

1. 唯一 cron 与 JSON 规则精确一致，没有其余临时新闻定时工作流。
2. 单元测试检查跨 UTC/北京时间日期、00:01 边界、非法旧版时间与无权限预览。
3. 不通过 `push`、PR、`workflow_dispatch` 冒充计划定时触发成功；必须存在 `event=schedule` 且路径为正式工作流的真实 GitHub Run ID。
4. 单独核实 PDF 清单、SMTP 回执以及用户 QQ 收件箱实际收件。
5. 连续多日记录自动启动与交付，不能将配置完成称作可靠性验收完成。
6. 未来若需要有保证的准时触发，应改为**一套**经过授权的外部调度源来调用相同生产入口，而非叠加更多 GitHub cron。
