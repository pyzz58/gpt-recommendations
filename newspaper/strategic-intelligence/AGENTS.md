## 实施约束

1. 核 GitHub 最新版本，直接依据 V5 的使命、九领域同等初始机会、六层 L1—L6、双刊、精选原作与逐件复制/翻译许可、证据、三时间和历史判断、全部现行审稿硬规则、四阶段门槛施工。遇到遗漏或章节冲突，先修订这份唯一说明书，不从其它资料拼接一套执行标准。
2. 第一阶段先制作真实完整的高质量周报样刊，验证原作 A 的有权全文及英文中文译文或原站直达导引、幕僚式顾问 B1、先懂后命名的帝师 B2、C 及 L5 审稿、重要主文机制教学、整刊反茧房与原件取证。第二阶段验证跨周研究、六份真实跨域案例和旧判断回放；第三阶段比较专业资料与多 Agent 的实际增益；第四阶段才扩大自动编排、交付、告警和备份。每一阶段保存实际产物、原始证据、失败和成本。
3. 系统只为用户本人制作供自行思考的杂志文档，不建答题、对话、多读者门户或学习画像。将稿件完成、来源许可、代码功能与出刊交付分开报告，不能把刊物质量写成用户已经掌握。旧结论保留原话及当时实际引用证据；后来发布或补录的资料不能倒填旧判断。知识卡被反证须修订并保留原版本。
4. 新的明确用户决定须在同一次规范变更中更新 V5 所有受影响章节、规则和验收；历史修改留在 Git 与非执行档案供审计即可。接手者不必理解旧提案为何被放弃。
5. 未获授权不得发正式邮件、启动生产部署或收费服务、进行交易、改日报或公开身份、密钥、私人及受限全文。报告提交版本与真实验证结果。
