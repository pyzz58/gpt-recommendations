# 内参系统｜从原始资讯到长期判断的端到端生产流程

> 这是逻辑流水线的**完整实施说明**，不是已经运行的生产系统。设计原则：清楚的工序、可定位中间产物、明确错误出口；可以由一套可重试Python管道实现，**不等于必须拥有十二个Agent**。
> 双产品：每周深度周报＋每年综合战略年报。独立于既有每日早报。

## 0. 工作流的全局不变量
1. **来源真实优先**：候选新闻≠证据；具体来源与相关原文/合法短摘或数据必须可定位。
2. **无来源不推论**：每个关键事实都带出处、源时间与获取时间；模型新增“听起来合理”的事实属于阻断级错误。
3. **日报非前置**：即使日报没有输出，内参仍要发现、研究、出版（可能选择少发）。
4. **双队列反茧房**：核心关注美股+创业；探索队列独立寻找陌生、低热度、高影响的全球信号。
5. **事实—知识—判断分层**：原话/事实/机构观点/推理/预测/未知不能揉成一团。
6. **失败可重试和可审计**：每个job有ID、状态、输入哈希、产物和错误；同一刊次不能因重试重复发邮件。
7. **外部访问合法合规**：阅读权限与模型处理权限区别登记；禁止自动进入付费墙、抓取未授权数据。
8. **文章深度动态**：不硬凑九栏目、篇数、字数；重要性和教育价值决定篇幅，低价值条目可不刊登。

## 1. 阶段A：独立全球发现（步骤01）

**输入**：`SOURCE_REGISTRY.json`现124个活跃候选、多语主流媒体、各行业公开机构研究目录、监管原文、公告与学术数据；GDELT/Media Cloud可提供附加新闻线索；旧日报仅只读可选输入。

**执行方式**：
- 按每源允许方式优先原生RSS/Atom/API/公开公告、Newsletter或公开报告目录，不要求首版124个全部集成。
- 低成本先读取标题、摘要、发布时间、原始链接、来源/地区/语言、所属栏目；需要正文时再依法获取。
- 过滤垃圾域名/重复URL/广告，记录合规授权状态和不能访问原因。
- 保存`DiscoveryCandidate`：候选ID、原始URL、聚合器URL（若有）、published_at、discovered_at、source_id、source_language、geo、topics、channel、first_seen_at、status。
- **费用控制**：绝大多数候选仅做程序化索引，少量入选才调用LLM。

**退出条件**：有可以溯源的候选池、覆盖统计、成功/失败源概况；零新闻也要保存空结果原因。

**失败处理**：单来源不可用只标source_health故障，不让其他来源失败；索引源下线回退原生订阅；禁止把失败伪装为“0条新闻”。

## 2. 阶段B：事件还原与血缘（步骤02）

**输入**：候选池。

**规则**：
- 规范URL、时间区/UTC、原标题、语种、媒体所有权；获取文章更新版本与发布时点。
- 发现同一媒体不同语言改写、地方转发及媒体对其他媒体的引用关系。
- 用规则/文本相似/实体事件时间窗聚成`EventCluster`；如果内容不同则拆分，保留人工修正记录。
- 对每条主张保存“原始机构声明/媒体转述/独立核实/匿名声称”的层级，避免转载链计成多份证据。
- **不因为文章量多就证明事件属实**；为真正分歧建立事件内 competing_accounts 视图。

**输出**：EventCluster、SourceLineage、DedupDecision 与可信的原发指针。

**失败处理**：无法确定是否同事件就保留临时独立事件及`needs_review`，不强制误合并；发生错误可撤销与审计。

## 3. 阶段C：反茧房与选题（步骤03—04）

**输入**：事件池、来源覆盖审计、已有长期主题和最近出版记录。

**双队列**：
- `core`：与美股投资、创业、金融政策、核心科技相关的高价值议题。
- `exploration`：不同国家/不同制度/不熟悉行业/地方媒体的重要而少被追踪的议题；不能被用户持仓或热点榜单排除。

**评分建议（非绝对数学真理）**：全球影响25、结构长期性25、资本/商业意义20、证据可检验性15、时效10、历史连续5，总计100。资源倾向另依九栏目基准分配，**证据门槛先于评判其可投性**。

对每一候选写一段选或不选理由：
- 此事新变化是什么？影响机制何在？是否重要到需要顾问教学？
- 现在的可靠证据足够吗？若不够，先`watch`或`research_pending`，不把传闻当确定新闻。
- 如果只来自单个机构/媒体，对应的潜在偏误及可区分的反证在哪里？
- 是否有跨月长线主题更新？是否正在遗漏陌生高价值区域？

**研究投入**：L1简报（可靠事实＋基本机制）、L2聚焦研究（多来源+案例+条件情景）、L3深度专题（原始数据/历史/竞争解释/具体推演）。不是“选择L3就必须写20页”，而是证据和教学任务决定投入。

**输出**：`TopicDecision`、研究问题、截止时间、source leads、研究深度、栏目、主编排序、跳过原因与反偏好条目。

## 4. 阶段D：证据研究（步骤05—06）

**先研究，后成文**。对每个被选主题先生成研究计划：
1. 要回答的关键问题与最可能影响结论的未知是什么？
2. 有哪些一手官方/财务/技术材料？取得时间/版本/发布日期？
3. 哪些关键事实需要两条真正独立的证据链？哪些本身就是各方争议陈述？
4. 已经存在的解释有哪些？最强支持/反对证据是什么？
5. 历史背景是否真的可比？哪些重要条件发生变化？
6. 哪些数学、行业知识和因果机制必须教授？是否存在非线性风险？
7. 到什么程度可以结束？何时`INSUFFICIENT_EVIDENCE`而停止？

**研究行为**：
- 先检索原始政策、财报、法律文本、企业公告、临床试验注册、学术论文、官方行业数据；媒体作为现场和争议补充。
- 机构观点需记录机构可能拥有的业务利益。大银行和大咨询的高知名度不能替代核验。
- 引用必须指到真实URL/文件/页码/段落/版本/截点，外部原文可能依法只能保留元数据与短摘。
- 数字要查分母、单位、币种、汇率时点、统计口径，核对环比/同比、样本来源、披露延迟。
- 论文要区分预印本、同行评议、公司宣传、基准复现；医药区分临床试验注册、结果发表、监管批准。
- 政治/军事争议多方声称应明确归属、核验力与实际制度约束；不得猜测秘密交易。
- 投资研究区分财务实际、市场预期、估值假设、风险溢价和无法预测事件。
- 创业研究区分融资/热度、可重复收入、单位经济性和市场可达性。

**输出**：`EvidencePacket`、`ClaimRegister`、`HypothesisSet`、`UncertaintyRegister`及链接校验结果。数据不足不得推进到确定性结论；可以形成“证据不足专题”但必须标注。

## 4.5 V4.1新增核心步骤：开放式世界机制发现（在证据研究之后、顾问教学之前）

**第一性优先级**：[OPEN_ENDED_WORLD_MODEL.md](OPEN_ENDED_WORLD_MODEL.md) M01—M12。九栏只负责发现入口和学科核证，**不限定文章最终教授什么知识**。

1. 从已核事实、历史基线和预期差提炼真实谜题（Puzzle），不用标题预先设定原因。
2. 从结果倒推必要条件，并跨技术/法律/组织/信息/资金/人性/文化/历史挑选可能机制。
3. 建立竞争解释及每条因果箭头的证据、反证、未知、关键中介变量。
4. 选最有解释力、最值得教、可迁移且有证据的机制，或坦承无法区分，绝不套入“都是利益/人性/供需”的大词。
5. 顾问据此分析现实行动与决策限制，导师解释正式学科知识、费曼示例、历史/现实案例与陌生情境迁移。
6. **导师发现机制不能解释事实或反例时，必须退回证据研究或机制选择**，留下RevisionLog；一次生成后只作文字润色不是合格流程。
7. 独立审核验证事实/学科/因果/反方/迁移，不能用模型自评分证明质量。

**必留中间物**：Observation, Puzzle, MechanismCandidates, CausalTest, ChosenMechanism, AlternativesRejectedWithReasons, AdvisorAnalysis, LearningUnit, RevisionLog；实际不存在或无证据则标\`RESEARCH_PENDING\`。本流程仍为设计，非运行软件。

## 5. 阶段E：首席顾问教学成稿（步骤07）

输入必须是通过基本证据确认的研究包，而不是没有来源的新闻标题。

写稿结构是**自然的研究叙事**，不强制文章出现七个固定标题；顾问在内部按七层教学核查：
1. 到底发生了什么；
2. 为什么重要；
3. 有哪些必须先学的基础知识；
4. 参与者的激励/约束/行为/因果机制；
5. 能够用一个数字、图、案例或类比讲清吗？边界和反例是什么；
6. 如果多种解释都成立，如何用未来证据区分，什么情景会推翻现在判断；
7. 下次读者自己分析同类事件时可以复用的一个方法。

写一段**忠于公开可核实原文的记者式报道**，之后自然进入专业、具体、用例子讲透的顾问讲解。保留必要时间线、关键数字与不同方表述，不能写成100字快讯，也不能大段复制受版权保护的原文。

**输出**：`AdvisorDraft`，可附概念卡`ConceptDraft`、机制图文字描述、原始claim与正文位置映射。

## 6. 阶段F：独立审核、主编与出版（步骤08—10）

审核人/审核LLM**不沿用撰稿模型的“我已经看过所以没问题”自我背书**；必须重新读取证据映射、抽查关键来源、寻找强反方和错误解释。

质量100：来源20、机制20、反证不确定性15、历史连续15、认知增量15、决策启发10、可读性5。建议>=85作为候选，70—84返工，<70拒绝；**得分不能覆盖硬阻断**。硬阻断包括：无来源关键事实、错误数字/引用、伪造采访、偷换事实与主张、明知重要反证仍省略、违规获取、无标签预测。

返回`ReviewDecision{PASS|REVISE|BLOCK}`：明确问题位置、严重程度、证据、修复动作。REVISE必须新版本重审；BLOCK保持可审计，不发送。必要时人工主编最终裁定，模型分数不构成真实世界证明。

**主编**：
- 只合并通过审核的稿件；
- 删除跨文重复、保持术语/观点与证据时间一致；
- 标记概念与长期论题关联；
- 容许不同作者分析不一致，但必须显示具体证据分歧，不能简单调和成假的一致。
- 按阅读顺序构建一个有智力结构的整本内参，不必“九栏目九篇新闻”机械排序。

**出版与版式验收**：
- Markdown做权威定稿；
- 从同一稿件渲染HTML邮件、可选PDF和完整参考引用；
- 页面和目录可导航，中文专业语体自然，关键概念可查，来源透明；
- 短导读用于快速决策阅读，正文必须足够深入；**不要用“摘要”代替内参全文**；
- 大稿按章生成并核对章数、字数、引用、跨章内容、格式与图表假设；
- 校对所有外文翻译与术语，避免逐句直译的AI腔。

**输出**：`ApprovedEdition`、`PublishArtifacts`、`ContentQaReport`。

## 7. 阶段G：交付、长期记忆和持续更新（步骤11—12）

**交付状态机**：
```text
draft → research_verified → editorial_pass → rendered → queued
       → attempted → provider_accepted → delivery_confirmed_if_available
               ↘ failed_retryable / failed_permanent
```
用户未批准时终止在`rendered`或更早的dry_run状态，不得进入queued；不得凭SMTP/API已接受即宣称“收件箱已收到”。

幂等键：`edition_id + version + channel + recipient_group`。记录发送尝试次数、响应ID、提供商状态、失败日志，避免重试造成重发。收件地址、定时任务、密钥均需用户批准。

**长期归档**：
- 证据/出处/出版稿/审稿日志/失败事件/成本全留可溯源指针；
- 主题、认知原理、判断版本各自存储，源记录合法可保存的原件不被AI小摘要替代；
- 出现重大新证据时重新检查过去的预测或观点，按当时可得的信息比较新证据；
- 当读者几个月后说“把美国债务/保险合作/AI电力瓶颈那部分找出来”，须找到当年完整相关论据、版本、源引用和后续变化，不能生成不存在的旧文；
- 用户对文章的“没讲明白”“信息有偏”“这些内容对我无用”的反馈转为编辑规则变更或下一期研究线索，**不能暗改历史已出版文本**。

## 8. 周报和年报的操作区别

| 维度 | 周报（WEEKLY） | 年报（ANNUAL） |
|---|---|---|
| 主要时间单位 | 本周值得研究的改变 | 全年/长线主题的新综合与旧判断年度审计 |
| 主要输入 | 全球候选池与重要原始资料 | 全年周报+全年独立原始新闻和专业机构研究+历史判断版本 |
| 产出重心 | 高质量调查报道+顾问深入讲解 | 新综合的首席策略意见、框架与失误审计 |
| 逻辑错误 | 拼接七期日报 | 拼接全年周报 |
| 历史对照 | 有必要时用 | 必须明确哪些判断继续/变化/被证伪 |
| 独立发现 | 必须 | 可以重新独立检索，不只复述周报 |

## 9. 状态、失败路径与恢复

| 失败位置 | 状态/措施 | 保护要求 |
|---|---|---|
| 发现源临时坏 | `source_degraded`，保留其它渠道 | 不宣称覆盖全球全部 |
| 转载误合并 | `dedup_review`人工修复 | 保留映射和旧决定 |
| 源不可合法获取 | `access_restricted`，只用元信息 | 不绕过收费/反爬 |
| 文稿出现错误引用 | `BLOCK`并存错误详情 | 任何总评分不能放行 |
| 竞争性解释缺失 | `REVISE`，补反证 | 不发布迎合型结论 |
| 长报告意外截断 | `render_invalid`，重新编排 | 禁止发送缺章成品 |
| 模型成本超预算 | `budget_exhausted`，保留资料包 | 不静默缩短成摘要并称完成 |
| 邮件请求失败 | `delivery_failed`，保留产物 | 明确仅哪一步成功 |
| 历史判断被新事实推翻 | 追加新版`thesis`+证据 | 不覆盖旧判断 |
| 读者不理解 | 下一版解释改进 | 不假装已经掌握 |

## 10. 必须留下的每次运行审计
```text
job_id | edition_id | phase | started_at | finished_at | input_refs/hash
status | output_refs/hash | model/service_version | tokens | external_cost
source_count | verified_claim_count | flagged_claim_count | reviewer_decision
delivery_attempt_id | provider_status | retry_count | failure_reason
```
不能为了节省日志而让严重错误无法复盘。初版日志可JSONL，后续再PostgreSQL；敏感密钥和私人信息永不出现在公共仓库。

## 11. V4.0强制教学与年度流程接口

每个经选题的重大事件，在EvidencePacket后必须依[DOMAIN_TEACHING_PROTOCOLS.md](DOMAIN_TEACHING_PROTOCOLS.md)本领域逐项填写专业LearningUnit：实际现象/历史基线/权力资源图/决策选择/因果与数量级/正确学科定义/算例或法定程序/强反方/人性文化适用边界/陌生事件迁移。缺关键输入退回研究，缺机制和实例退回教学，严重编造直接BLOCK。最高阻断见[HARD_RULES.md](HARD_RULES.md)。

每周周报还要留下thesis/version/未来观测点。到年报周期时走[ANNUAL_REPORT_SPEC.md](ANNUAL_REPORT_SPEC.md)的A01—A12，首先读全年周报真实清单及缺期，再独立检索同年度新闻/机构原始数据，做遗漏、修订、因果链及旧判断年度审计后新写年报。年报生产**不能**简单把52份周报串起来；年报的实际投递仍需用户明确批准。
