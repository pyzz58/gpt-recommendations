# 内参系统｜最高优先级硬性规则（NON-NEGOTIABLE RULES）

> 版本 V4.0，2026-10-13；用户本次明确指令：**“禁止概念性总结，要明确方法，步骤，具体。这个要明确写入你的硬性规则里面。”**
>
> **适用范围**：今后任何对“内参系统”的需求讨论、规划、研究、撰稿、工程拆解、审稿、周报/年报、Codex交接及编辑修订。所有下级模板、提示词和程序必须遵守。冲突时：最新用户明确指示 ＞ 本文件的当前要求 ＞ DECISIONS/专题规范 ＞ 早期历史草案。任何修改仍须在决策台账保留原规则与取代记录。
>
> **状态**：本文件已经作为本项目内部制度建立，不等于已有软件强制校验器或外部智能体系统自动加载。未来开发必须把这些规则编写成审稿/自动化校验。

## R-001 严禁只做概念性总结（BLOCK）

不合格例：
- “采用第一性原理进行深度分析。”
- “引入费曼学习法，深入浅出。”
- “政治需要分析权力博弈。”
- “创业关注用户需求、CAC和LTV。”
- “建立世界结构变化雷达。”
- “参考中国传统文化和人性。”

**这些句子只描述意向，没有给出任何可执行方法。** 任何提出的方法，至少必须包含：
1. **作用目标**：要教会用户面对哪一类新问题时能够完成什么分析动作。
2. **输入与证据**：到底读取哪类原始事实、资料、数字、发布时间、来源以及需要哪些缺失信息。
3. **逐步操作**：按顺序至少写出可落实的调查、计算、查证、反证、讲解、复核步骤；说明条件分支与不适用时怎样停止。
4. **具体示范**：使用一个已核实的真实事件或**显著标为假设**的案例，具体拆解，而不是把原理名称当内容。
5. **隐含机制**：列出参与者、权力/预算/资金、目标、激励、约束、信息、因果与反馈；哪些是确凿事实、哪些是分析假说。
6. **知识教学**：给专业定义→通俗解释→具体数值/程序或人物选择集→案例反例→适用条件。
7. **最强反方**：另外什么解释也能解释现象？什么现实指标/文件可以区分？
8. **迁移与验收**：读者面对一个陌生案例怎么独立使用？怎样判定“懂了”而不仅是“看过”？
9. **历史接续**：如已有旧研究、旧结论、知识卡，必须调用原版本并说明新变化；未有则明确标记。
10. **实现责任**（技术方案时）：需要建立的具体函数/字段/文件、测试输入与验收结果、失败和成本；不能把计划描述成已实现。

**硬门槛**：缺失关键步骤/案例/反证/学科根基，审核结果必须为REVISE；出现伪造来源、法理/数学/医学重大错误、以动机推测冒充事实，结果为BLOCK。不因标题叫“帝师”或文字很长而放宽。

## R-002 从表现回溯到可检验的因果、博弈和认知规律

每个具有研究价值的主题按以下逻辑追踪：
\`\`\`text
可观察表象（谁在何时说/做了什么，哪些数字真的变了）
 → 原始事实与独立证据（法案、财报、试验、记录、现场）
 → 参与者与制度、预算、经济、物理、技术的硬约束
 → 各方可选行动、利益分配与代价（不是猜测人物内心）
 → 为什么在该约束下发生这种行为：竞争机制H1/H2/H3
 → 若机制成立会看到什么；哪些反例会推翻它
 → 现实后果与二阶影响（谁真的付钱/承担风险）
 → 教授读者下次独立分析的新问题、新方法
 → Theme/Thesis版本和未来观察指标
\`\`\`
**从表象下钻不是靠“一个隐藏阴谋”来解释所有现象**。机制必须具体、可核验、带适用范围；对未知坦率承认。

## R-003 九大板块分别有不可替代的学科教学标准

必须加载[DOMAIN_TEACHING_PROTOCOLS.md](DOMAIN_TEACHING_PROTOCOLS.md)对应领域规则。不能用“一张通用政治/金融/创业六段提示词”覆盖：
- 美股需现金流、市场预期、贴现、资本配置、风险；
- 创业需买方、客户价值兑现、单位经济、获客、留存、进入门槛；
- 科技需科学证据、工程规模化、物理限制、TCO、付费采用；
- 宏观需财政/货币权限、数据定义、传导机制和时滞；
- 中美需两国**不同制度**、政策程序、事实核对与互动反馈；
- 地缘政治需决策能力、军事/经济资源、承诺和真实信号；
- 企业竞争需利润池、价值链、五力/替代、组织激励与长期资本配置；
- 社会消费需人口/调查因果、分配与制度差异；
- 战略研究室需跨领域关系、反常信号、历史命题审计和强反证。

每篇只加载相关必要知识，不机械遍历全部词条；但**出现相关概念时不能一句带过**。

## R-004 中国传统文化与人性：可用，且有严谨边界

用户要求讲透人性、博弈与中国传统文化，必须做到**从具体文本/历史事件/可核查行为出发**：
- 例如《孙子兵法》的虚实、势、知彼知己，可用来解释信息不对称、信号与承诺；
- 《史记》的具体历史事件可用作制度/政治选择的案例，但必须审查史料来源、时代差异与现代制度不可直接类比；
- 儒家义利之辨、《孟子》的民心理念、《韩非子》的制度与激励、《道德经》的反向反馈等可作为**有明确来源和局限的思想透镜**；
- 不能把传统思想称为经科学验证的普适因果律，也不能依“某国人天性”“人性必然”下结论；
- 人性/动机分析使用可观察行为、公开约束和多种竞争假设，区分利己、身份、信念、声望、恐惧、互惠、道德承诺；
- 如果中国传统文化不适用于本期事实，则注明不适用，**不强行套典故**。

完整应用和反例见[HUMAN_NATURE_AND_CLASSICAL_LENSES.md](HUMAN_NATURE_AND_CLASSICAL_LENSES.md)。

## R-005 不能把“读完”说成“教会”

- \`TAUGHT\`只说明报告讲解过；\`PRACTICED\`需用户实际练习；\`DEMONSTRATED\`需用户在陌生场景正确独立迁移。
- 每篇需要一个**迁移问题和可复用判断步骤**，不必须要求用户真的做测试。
- 用户不愿参与问答时不能标记已掌握，更不能推断学习进展。
- 若读者学不会，先判断卡在术语、因果、算例、证据还是迁移，针对环节重新讲，不堆更多抽象说教。

## R-006 只发行“周报＋年报”

**正式内参出版产品**：
- \`WEEKLY\` 《内参系统·全球战略周报》：从全球独立发现、高价值原始来源与主题历史构成深入研究。
- \`ANNUAL\` 《内参系统·全球战略年报》：以全年已出版周报、全年新闻原始来源/机构研究和**年末新增独立核验的材料**为基础，重新构建年度变化、结构主题、失误审计与未来情景。

**月报/MONTHLY不是当前产品**；过去月报内容仅属于历史提案，不得生成、调度、实施或引用为现行规划。**年报不是52份周报合订**，必须重查全年一手数据与事件、做跨期反证、完整年度比较、历史判断对照及时间截点审计。年报具体编排见[ANNUAL_REPORT_SPEC.md](ANNUAL_REPORT_SPEC.md)。

日报为已有另一个系统，维持隔离；重大事件特刊仍是未批准的未来选项，不能视为第三个正式发行产品。

## R-007 用户认可的“说得对/同意”必须保真留档

每当用户在内参项目上下文明确说“你说的对”“我同意”“全部同意”“这个方向好”或其他赞同，**下一个能写入仓库的工作轮次必须记录**：
1. 用户实际引语和日期、上下文；
2. 用户认可的**紧邻具体方案/段落/方法**，不得概括成宽泛空话；
3. 已认可的“设计方向”与“是否授权真正执行”严格分开；
4. 链接到**方案原始详细位置**（能定位原对话时保留会话线索；不能定位时标未取回）；
5. 若已建文档尚缺细节，应先补完整方法再标记为“已归档”，不只记录批准文字；
6. 更新[ENDORSEMENT_LEDGER.md](ENDORSEMENT_LEDGER.md)、[DECISIONS.md](DECISIONS.md)和相关执行文档，必要时升级[TRACEABILITY_MATRIX.md](TRACEABILITY_MATRIX.md)；
7. 无法访问仓库/工具时明确告诉用户未保存，不得声称完成或代替为自动后台承诺。

**重要**：普通客套赞扬只代表对应内容的满意度；“同意一个设计提议”不自动等于准许支付费用、发送邮件、创建定时任务或修改日报。任何用户后来的明确修改（如月报→年报）优先，旧认可继续保存在历史记录而不再执行。

## R-008 研究机构式而非摘要机式交付
五类能力必须能各自产出成果：新闻发现、跨期情报、金融研究、咨询式机制拆解、家族办公室的多年判断与纠错；三种雷达包括战略判断追踪、全球商业机会、世界结构反常。参考[INTELLIGENCE_OPERATING_MODEL.md](INTELLIGENCE_OPERATING_MODEL.md)。不需要一开始部署十几个独立Agent。

## R-009 事实与许可的不可越界线
- 原始公开文件及其发表日期、版权许可、转载链、事实/解释/猜测分别标记；未经许可不得复制受限全文。
- 欲引用公开投行/银行/智库观点需注明其身份、利益与模型假设；不能把机构预测当事实。
- 个人隐私、邮箱、投资账户、API key 不上传到公开GitHub。
- 未经用户授权不得自动发布周报/年报、发送邮件、建立生产定时任务、付费、修改日报、对证券账户交易。
- 目前124条活跃候选来源与六条已放弃来源状态保持不变，暂停其余来源技术验证。

## R-010 每个研发/修订工单必须是可复现的执行协议

示例禁止：“完善顾问能力，提高深度。”
合格例：
\`\`\`yaml
task_id: LEARN-POLITICS-01
input_fixture: "有公开来源指针的真实政策事件；另备一个明确假设的反例"
steps:
  - "取制度原始文本，确认立法/行政/财政/司法谁有管辖权"
  - "提取实际投票/预算/正式施行时间，区分政治言论与法律效力"
  - "列3种竞争解释及最强证据，指出哪份未来记录可区分"
  - "写严格制度定义→生活例子→类比失效条件→陌生国家案例"
output: "ClaimRegister + MechanismChain + LearningUnit + Draft + Review"
acceptance:
  - "关键法律权力有准确来源"
  - "真实事实与猜测独立标注"
  - "文章教会一个可迁移的判断程序"
  - "独立审稿遇失实可BLOCK"
excluded_actions: "不发送邮件、不新增定时任务、不改日报"
\`\`\`

**以后看任何PR或任何周报/年报，只要缺少“方法—操作步骤—示例—失败条件—验证证据”，就不能标已完成。**

## 硬性规则的技术落地路径
1. **现在（设计）**：本文件、领域协议、技能规范、模板、测试清单和决策台账进入GitHub。
2. **后续样刊**：用一条真实可核查的新闻逐项人工检查R001—R010，保留阻断与返工日志。
3. **后续MVP**：将LearningUnit字段和ReviewDecision硬门禁写成JSON Schema/测试；缺证据或无具体分析步骤时拒绝进入编辑通过状态。
4. **未来生产**：自动化仅用于辅助，来源许可与用户批准仍独立审查；禁止用LLM自评分声称真正教会读者。
