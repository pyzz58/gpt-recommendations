# 分步落地路线：每步的动作、产出与门禁

> 当前仅是未来执行手册；**所有步骤尚未执行**。未来执行时先备份、做代码审计及人类批准。

## Phase 0 — 验证内容价值（不依赖完整自动化）
**0.1 现状调查**：读newspaper现有目录、Actions、时区、触发器、发送渠道、历史故障记录、数据存储与权限。输出只读审计，不擅改。
**0.2 独立样稿发现**：不允许从日报精选结果限定选题。用独立媒体搜索/广域索引与原生免费公开新闻源挑选6个有原始来源的真实议题：美股2、创业1、政治1、科技1、宏观1；故意包含日报未入选的高价值议题。冻结资料时间截点、保留发现渠道和来源清单。
**0.3 建研究规范**：将EDITORIAL_POLICY与ADVISOR_PEDAGOGY转成版本化模板/Schema，包括证据表、竞争性解释、教学七层、审查门禁。
**0.4 生成样稿**：一套研究流程，逐篇先出EvidencePacket，后AdvisorDraft，不得先写结论再找引用。
**0.5 双重评测**：编辑评分、引用抽检、反方观点、公平度、教学理解/迁移任务；收集读者对“是否真正懂了”的反馈。
**0.6 门禁**：六例能达到真实来源核查、清晰机制教学、可靠反证；至少部分高价值主题独立于日报发现，并披露未覆盖的地区/语种。若不达标先改规范，不引入更多Agent。

## Phase 1 — 最小可用周刊
**1.1 独立代码目录**：只在strategic-intelligence下新增文件；不得修改日报生产流程。
**1.2 独立全球发现层**：先核查SOURCE_REGISTRY.md/json的130个候选和SOURCE_ACCESS_BLOCKLIST.md明确移出的付费/AI限制来源，按SOURCE_VERIFICATION_PLAYBOOK.md执行逐源网络/API/RSS实际解析烟测（参见ACCESS_AUDIT_2026-10-13.md已进行的Web抽样和仍未解决的C类访问），合法开源回退（SOURCE_TOOLING_RESEARCH.md）、状态转换和来源健康日志，再按采集优先级接入。先建立SourceRegistry，登记媒体国家/语言/来源类型/许可/可用性。评估一至两个广域索引（GDELT/Media Cloud等候选）+ 全球多语主流媒体原生RSS/API/Sitemap + 官方披露与财报，构建**不依赖日报的候选池**。记录事件发布时间、采集时间和原始URL血缘；跨语去重及转引识别。尊重收费与版权限制。详见SOURCE_DISCOVERY.md。
**1.3 全球多样性与候选评分**：来源/地区/语言覆盖审计、探索队列及漏报抽样；重要性与证据门槛分离。美股/创业仅在研究资源分配阶段优先，不能阻断全球发现；重大事件越级审核。
**1.4 统一研究引擎**：可先简单Python管道+LLM工具；测试GPT Researcher若显著提升再引入。每阶段结构化产物和失败状态可见。
**1.5 顾问教学**：按领域策略加载教学知识；输出要包含例子、反例、适用边界、下一次自分析方法。
**1.6 审核门禁**：核验原始链接、关键论断、事实/推断标签、观点多样性；阻断级错误绝不能交付。
**1.7 编排出版**：Markdown为主稿，导出HTML及PDF，适应长篇章节；独立版本和哈希。
**1.8 测试交付**：先干跑、模拟失败、人工测试邮件地址；收件人/调度时间需要另行授权；不得修改日报已有邮件。
**1.9 验收**：至少连续多期预演，并单独测试“日报断流后全球发现独立可用”、某个聚合器失效、跨语言同事件重复、美国/中国之外的重要报道、陌生非热点主题被选入，以及网络失败、HTML/PDF出错等；只有真实交付核验后才建议开启正式周刊。

## Phase 2 — 月报与长期档案
**2.1 设计数据库**：建立source/event/entity/theme/thesis/edition/concept及版本审计；维护迁移脚本和备份。
**2.2 历史导入**：只迁移有可靠来源/用户许可的历史研究；记录原始文件与版本，不把摘要替换原件。
**2.3 跨期主题**：长期编号，关联每期新增证据与当时判断，支持“过去在什么信息下怎么想”。
**2.4 预测审计**：事前定义可验证命题和截止日期，过期复盘结论与预测偏差。
**2.5 月报总编辑**：从新增证据出发，重评上月观点，挑美股/创业核心专题，输出“判断变化”与“我们错在哪里”。
**2.6 反茧房审计**：从采集源头检查跨国、跨语种、不同利益位置及非日报独立选题；抽查转载复读、遗漏的重要在地报道、最强反方分析和读者偏好迎合。
**2.7 验收**：能忠实回溯旧版判断、来源和修正；月报不能只拼接周报；知识卡片可检索且不自动宣称已掌握。

## Phase 3 — 按价值增加专业能力
在证据表明确瓶颈后，逐项评估金融接口（OpenBB）、网站更新监控、pgvector、Langfuse、更高推理模型、并行研究与知识图谱。每引入一个项目必须证明可观测的收益（质量、成本、可靠性或速度），运行维护与许可证可控，否则不引入。

## 未来AI任务规则
每阶段先提出小步计划，核对权限和受影响文件；改动必须最小；出自动测试和人工可读验收结果；失败先记录问题再修；生产部署/发邮件/付费服务必须再获得用户明确指令。**禁止因阅读本规划而自动执行。**
