# 独立全球新闻发现系统：媒体覆盖、前沿信号与信息多样性

> 版本：2026-10-13 修订；**规划，尚未实施**。本文件覆盖统一研究引擎的最上游发现层，不更改现有日报运行方式。

## 1. 用户明确的设计决策
**周刊/月报研究选题不得以每日新闻早报为唯一来源或主要筛选前置条件。** 日报本身是压缩筛选后的产品，若周刊仅从日报二次挑选，会累积采样盲区与选择偏差。

周刊/月报必须**独立扫描全球范围内合法可免费访问的主流媒体和多语言信息源**，同时接入公开的一手信息：政府、监管、法院、统计机构、央行、公司财报/公告、研究论文、技术机构。日报只是补充信号和线索；二者不得形成“日报筛选→周刊只能选择入选日报的条目”的硬依赖。

“全球所有免费的主流媒体”是**最大化覆盖目标**而非技术上保证穷尽每一家媒体或自动免费阅读受限内容。所有候选来源的开放程度、访问条款、RSS/API可用性和更新频率都必须验证和记录；不绕过收费墙/反爬措施，尊重 robots、许可证与合理请求速率。免费阅读≠授权全文复制、训练或二次分发。

## 2. 核心发现策略：广覆盖、低成本、深核查
**发现层**尽量广而灵活；**研究层**只对少量高价值事件深挖；**出版层**只刊登核实且有认知价值的内容。

- L0 全球广域发现：新闻索引/聚合、公开RSS、公开Sitemap、关键词+语义扩展、多语检索、地区主动轮换，尽量覆盖英文、中文和主要世界语言。记录索引覆盖偏差与潜在漏报。
- L1 来源还原：解析规范化链接与原发媒体、作者、地点、发布时间，识别同一原新闻的转引/转载与更新，避免把转载数量误当独立证据。
- L2 事件去重：把不同语言的相同事件按事件ID聚合，同时保留报道差异与来源。区分“广为报道”与“真实已证实”。
- L3 专题深究：筛出重要事件后回到来源原文、官方文件和实际数据，收集最强反方资料；对引用可回溯性作校验。
- L4 长期信号：监控用户不熟悉但具重大潜在影响的区域、行业与结构性变化；积累到长期主题而非强制每周刊登。

## 3. 候选新闻发现基础设施（正式开发时重新核验）
1. **GDELT Project**：全球多语种新闻覆盖/事件与元数据索引。官方说明它对大量语言媒体进行监测与翻译，适合作为“发现候选、地区/趋势异常、跨国报道比较”的一个入口。非完整原文存储和绝对真相源。官方参考：https://gdeltproject.org/data.html 和 https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/
2. **Media Cloud**：可搜全球新闻档案与来源目录；按来源/集合观察媒体覆盖，适合作为第二种独立发现与来源检查渠道。其FAQ说明版权限制使其无法开放新闻全文，通常可以提供URL；API使用及限额另行核查。https://www.mediacloud.org/documentation 和 https://www.mediacloud.org/documentation/faqs
3. **新闻机构原生RSS/API及官方公开Sitemap**：以可合法访问的媒体自身链接为权威落点；不把聚合器标题直接视为事实核查完毕。
4. **RSSHub**：当个别重要公开来源无RSS但有合法采集路径时作为**备选**工具，先审核许可、源站访问规则、稳定性和安全性，绝不为追求全覆盖无条件抓取。https://github.com/DIYgod/RSSHub
5. **官方及公开披露**：美股优先SEC EDGAR、上市公司投资者关系与财报；宏观优先央行及统计局；政治优先政府原文和独立可靠报道；科技优先论文/工程实测/标准及行业公开资料。准确数据可另接专业公开API，许可证与更新频率单独审查。

可比较搜索引擎、新闻搜索页、公开RSS与上述聚合渠道，但不要过早让单一平台成为强依赖；来源某一天故障应可切换和降级。工具均仅为**候选**，没有任何实际 API 集成或付费承诺。

## 4. 全球媒体来源库：动态注册，不等同于锁定固定白名单
SourceRegistry 记录：source_id、名称、国家/地区、原始语言、报道领域、来源类型(media/primary/research/aggregator)、独立所有权/转载关系、站点/Feed/API入口、访问许可、可用性、最后成功访问、内容定位、时效、质量记录、是否可能带有机构立场、覆盖盲点。来源审查后动态增删，需同时保留停用历史。

**初始地域覆盖池（举例而非保证已接入或全站免费）**：
- 美国/加拿大：AP、Reuters、NPR、CBC等公开可访问栏目及地方/专业媒体。
- 欧洲：BBC、DW、France 24、Euronews及当地语言主流媒体。
- 中国/东亚：新华社、财新可公开的部分报道、澎湃新闻、NHK World、韩国主流媒体等；注意市场数据和政治叙事需交叉核查。
- 南亚/东南亚：The Hindu、CNA、新加坡及各地重要英文/本地语媒体。
- 中东/非洲：Al Jazeera、各地主要新闻机构与本地报道；不能仅靠英语国际版。
- 拉美/大洋洲：主要西/葡语媒体、ABC Australia、RNZ及其他本地媒体。

具体是否有RSS、是否免费、地区封锁、版权及接口可用性均须逐家核验；不预设名单等于穷尽。大媒体与本地报道互补，英文报道之外保留原语言线索。不要把内容倾向标签当质量分数。

## 5. 反信息茧房的采集层设计
**不是仅在稿件结尾添加“反方观点”，而是从发现入口反偏差**：
1. 时间与地理覆盖：每轮统计来源所覆盖地区、语言、新闻领域、发行机构与独立媒体集团；监视缺口。
2. **双队列**：核心队列偏重美股与创业；探索队列独立寻找全球重大变化、非热门议题和原有偏好之外的线索，不能被核心权重清零。
3. 主动反向搜索：对高影响问题寻找不同制度环境、不同利益相关方的来源及最强竞争性假设。
4. 异议与少数重要信号：报道频次低但可信度和结构性影响高的事件，保留进入编辑复核的路径。
5. 独立来源计数：十家媒体转载同一稿件只算一条原始证据链；记录影响范围，但不伪装十份独立证实。
6. 抽样漏报检查：定期随机选取在地媒体/官方公告，检查是否被广域发现覆盖，估计盲点并调整配置。
7. 重要来源缺失提示：主流来源的限制、索引地区偏差、翻译误差应在内部审计中可见。

**覆盖强度不等于真伪**；数据可视化应区分报道量、来源独立性、证据质量与事件本身重大程度。

## 6. 研究引擎选题的两阶段闸门
- **发现池**：广泛收集，不受日报数量或个人既有喜好限制；可以包含未核实的“线索”，但必须标明状态。
- **证据与重要性审核**：事实来源、影响、结构性意义、创新/商业价值、地域与立场多样性、历史主题新变化；剔除垃圾站/搬运/未经核实宣称。
- **深度研究池**：按L1/L2/L3成本等级使用LLM和检索，选题权重25%美股+25%创业是研究资源优先级，非采集阻断阈值。
- **出版池**：主编按价值动态挑选；没有相关证据就不凑栏目，不得单一媒体垄断重大判断。

## 7. 建议的未来技术数据结构与工作流
```text
[全球新闻索引 GDELT/MediaCloud 等] ----+
[各地区/语言的媒体RSS/API/Sitemap] ---+---> source registry / scheduler
[官方披露、论文、上市公司数据] -------+            |
[现有日报（只读辅助线索）] ----------+            v
                                               normalized candidates
                                            → URL/事件/来源血缘去重
                                            → 地区/语言/题材/立场覆盖审计
                                            → 重要性与证据审核
                                            → 少数主题深度研究
                                            → 顾问教学+反方审核
                                            → 周刊/月报+长期记录
```
推荐结构化对象：
`DiscoveryCandidate{candidate_id,source_id,source_type,original_url,aggregator_url?,original_language,region,published_at,discovered_at,topics[],event_key?,trace[],availability_status,verification_status,discovery_channel}`
`CoverageAudit{period,regions[],languages[],media_groups[],primary_sources[],missing_segments[],recirculation_clusters[],sampling_checks[],notes}`
`SourceHealth{source_id,last_attempt,last_success,error_type,rate_limit,license_status,enabled,notes}`

每个资讯发现链路应包含query+结果版本+取样时间和检索来源，不凭空声称“扫遍全部新闻”。若聚合器无原始链接或文章来源不可合法核验，只能作为待查线索，不能独立支持重大结论。

## 8. 具体未来落地顺序（非已执行）
**Step 1**：编写来源注册表和许可证核验模板，按区域/语言初建多样性媒体池及官方来源池。
**Step 2**：用一至两个广域索引跑离线/小规模发现基准，同时接若干重要原生RSS，建立原始URL血缘与新闻去重。
**Step 3**：按发现广度、独立性、漏报、准确性、成本和延迟评测聚合器；任何平台故障不能令整个选题池归零。
**Step 4**：实施双队列与盲点抽检，确认周刊选题可以完全不通过日报而产生。
**Step 5**：将入选主题接入已规划的研究→顾问教学→独立审稿→长期档案管道。
**Step 6**：按覆盖审计和用户实际阅读价值迭代来源池，不为“更多来源”而无上限扩容。

## 9. 硬性验收
- 断开/清空日报输入后，全球发现层仍能独立产生跨地区、跨语言、多主题候选，并按来源回溯。
- 即使某一家新闻聚合器不可用，原生媒体和另一发现渠道仍可工作；记录降级状态。
- 多家媒体转载同一来源能被聚合为同一事件并识别非独立证据。
- 选题池存在非日报、非美国/中国、非用户现有偏好线索；重大且证据充分者可刊登。
- 代表性样本可记录覆盖盲区、不可访问来源、发布时间和采集时间。
- 只使用许可数据；没有免费权限的全文不抓取、不大段复制；引用与结论能返回可靠原文或公开披露。
- 不通过“给日报再加几个频道”来冒充独立全球发现。

## 10. 常见错误
- 把GDELT/Media Cloud当成全球所有媒体、所有文章的完整视图。
- 把新闻聚合器中的摘要当作已核实一手事实。
- 把“媒体覆盖全球”理解成无需多语言/地区来源平衡。
- 以美股/创业50%选题权重限制发现环节，造成研究盲区。
- 忽略新闻机构间转载关系、编译信息缺失与延迟。
- 以无授权的全站抓取替代合法RSS/API/公开摘要。
