# 科学交付回流与首席整合交接

日期：2026-11-06（Pacific/Auckland）。依据：最高思想D-022/D-024、§7.3、§7.6—7.7；技术TR-05/TR-08/TR-11/TR-19，原工作包W05/W11/W21。

本轮补齐已有需求，不改组织结构或最高思想原则。研究任务的交付验收与首席科学家的综合判断是两次不同交付；阴性或缺证结果可以是合格交付，不能要求结论必须利好。

## 业务链

1. 用户选择研究范围，科学首席形成问题，运营落实计划。新计划默认启用scientific_feedback；最多19个业务节点，另由宿主保留一个A02 chief-integration节点。
2. 专业岗位运行后进入submitted。独立审核由指定A25/A26合同记录，绑定具体任务版本、实际交付run及hash。major/critical不能接受科学交付。
3. 退回时新运行收到旧输出与具体findings；通过后原交付及全部审核意见以agent_run类型引用进入下游。不能用状态完成标志代替内容交接。
4. 所有业务节点通过后，A02收到实际资料包和审核记录，输出ScientificUpdate：已回答问题、判断变化、未知、下一步理由和可选计划。该交付再次独立审核。
5. 整合通过后保存版本化项目事件，关联原计划、任务、run、审核与交付hash。等待/暂停/停止无新派工；继续/补证/修改在同一范围内生成关联计划并入队。
6. 后续计划保留原用户选择、研究目标、专业阶段及资源轮次。补证默认最多1轮（初始可设0—3），超过上限保留建议并暂停；不允许模型提高额度或跳过专业阶段门。

## 运行与真实性

- 当前运行仍只支持mock。默认fake首席输出“真实科学问题尚未回答、等待证据”，不会假装研究成功。
- 专业审核仍由owner代表独立岗位合同录入；规则审计和角色隔离不等于真人或非mock专业模型审查。真实模型接入、科学质量考核和现实机构闭环仍属于后续验收。
- 共享依赖只在单次读取遍历内复用核查，防止多分支图指数重复读取；下一次命令重新校验，不缓存过期结论。
- source/provider引用、任务当前输入、项目归属、审计阻断和交付hash在读取及执行时复核。过期、未验收、篡改或跨项目结果不能进入新研究。
- 历史计划不静默改写。scientific_feedback=false是历史/非科学接口兼容选项，此类计划不能作为科学反馈闭环验收。
- 回流更新的是项目保存的研究判断、上下文和计划，不是对模型权重的训练。

## ADC与猫肿瘤合成案例

这是流程验收输入，不是新研发标的选择，也不提出ADC疗效、安全或临床使用结论。

必须看到：原问题→A04合成资料包→major退回→重做新run→独立接受→A02实际接收资料与原异议→结构化判断→整合独立接受→关联补证计划已排队→下一轮达到上限后不再创建任务。

反例覆盖：未验收/跨项目交付、非法UUID、交付被改写、失效输入、整合遗漏输入、重复审核、等待/暂停/停止及外部委托建议。外部建议应保留并阻止自动执行，不能导致无限重试。

测试入口：services/core/tests/integration/test_scientific_feedback.py。原W11/W21接口回归显式保留非科学模式，新的科学闭环由专门用例检验；不能把关闭反馈后的旧用例视为新功能通过。
