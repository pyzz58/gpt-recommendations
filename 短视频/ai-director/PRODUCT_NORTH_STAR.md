# 产品北极星：文案 → 导演设计 → API 制作 → 审片返工 → 短视频

## 当前决定（2026-10-12，API 路线）

用户已明确同意在系统内接入 Seedance 等第三方视频 API。完整导演方案是制作依据；最终目标是回收真实镜头、审片、局部返工并完成短视频合成。当前先用《先吃饭》S02 的 8 秒对白镜头验证最小链路，详见 [API 审查](SEEDANCE_API_AUDIT.md)。

## 一句话定义

**用户提供文案，系统负责完整导演设计，调用第三方视频制作服务，管理候选镜头与审片返工，组织声音、字幕和剪辑合成，交付经过用户审核的短视频。**

系统使用第三方生成模型，不自研视频基础模型。制作包手动导出保留为兼容和故障备用路线。API 接口、视频回收与合成属于产品主线；专业创意质量与媒体效果仍须实测。

## 主线的标准流程

1. **输入文案**：识别故事母题、受众、平台、时长、事实风险、不可修改的信息。文案是唯一内容源；允许提炼删减，但改写须清楚告知并保留修订痕迹。
2. **内容导演/系列策划**：确定是否拆集，核心冲突、开头钩子、情绪曲线、反转与收束，人物和统一美术设定。
3. **专业镜头设计**：每镜承担的情节任务、绝对起止时间、场景、景别、构图、走位、角色脸部/肢体动作、物品位置、镜头运动、灯光、道具和逐秒节拍。
4. **声音与台词设计**：区分旁白（VO）、人物出镜对白、配音表演、对白起止、口型同步、背景声、拟音、BGM 与字幕。未经用户批准不可将导演备注变成实际旁白修订。
5. **动画/图形设计**：明确动态图形、文字图层、关键帧、时间轴、运动路径、合成层、特效与后期制作责任。没有动画需要时必须**明确写 none**，不能缺项。
6. **剪辑导演设计**：每镜前后如何接、转场类型、切点动机、镜间视线/动作/音乐匹配、停顿和节奏、转场所需前后余量、声音提前/延后、最终合成顺序。
7. **AI 制作交付**：按镜头选择 AI 视频、静态图后期、剪辑合成、实拍插入等。导出每个动作段的精确制作需求、角色/场景参考资产、生成候选提示词、失败替代方案及后期工作单。
8. **离线审查与交付**：校验时间轴、连续性、复杂动作可执行性、台词字幕对应、转场衔接、内容真实性、素材与授权风险，生成 JSON/Markdown/HTML 供用户人工批准。

9. **API 制作与回收**：由用户确认具体镜头、模型、素材及预算后提交，保存任务凭据、查询状态、及时下载视频，失败只重做获准的镜头。
10. **审片、返工与合成**：检查叙事、人物、动作、空间、对白口型和实际时长；按镜头版本修订，处理配音/音效/字幕/图形并合成整片，用户批准后交付。供应商任务成功不等于这一阶段通过。

## 制作依据：完整而可用的导演交付书

以 `director_workbook.py` 与 `director_workbook.json / director_workbook.md` 作为可审阅的制作依据，与后续视频任务和镜头版本关联。

| 每镜维度 | 必要结果 | 对应字段 |
|---|---|---|
| 故事 | 这一镜为什么存在、观众看到何种变化 | story |
| 台词/旁白 | 精确用词、配音起止、语气、字幕、口型 | script / speech |
| 表演动作 | 谁、用哪只手、从哪里走到哪里、每秒发生什么 | performance |
| 摄影 | 景别、运镜、轴线、起止画面及机位 | camera |
| 场景 | 场地、置景、灯光方向、画面风格 | set_and_lighting |
| 剪辑 | 入镜/出镜转场、切点依据、节奏与合成 | editing |
| 动画/特效 | 关键帧和图层、运动方式、后期安排 | animation / graphics |
| 声音 | 环境声、台词、BGM、拟音、声画连接 | sound |
| 制作 | 选用 AI 视频/静态/后期/实拍、参考资产及候选提示词 | production |
| 连续性 | 人脸、衣服、场景空间、手机/书等道具的镜间状态 | continuity |

**导演交付书不是提示词堆砌。** 各项必须先有合理的导演决策，才据此生成适配具体视频工具的指令；不能为了生成 Prompts 而牺牲故事节奏。

## 技术状态与质量门槛

- 已有 `plan.json`、`direction_v02.json`、`director_v2.py` 负责部分导演创意；新增 `director_workbook.py` 汇总全部部门，并明确揭示原系统遗漏的剪辑、动画、台词/VO 执行细节。
- **旧版兼容**：过去的专业导演方向稿缺少 `editing / animation / speech` 时，仍可生成导演**草稿**，但质量状态为 `creative_design_complete=false`，并列明待补项。
- **严格导演验收**：只有每镜具备明确的剪辑、动画（或 none）、对白/配音设计且与基础稿不矛盾，才能标记 `creative_design_complete=true`。这仍**不代表**视频生成成功、人工批准或允许付费。
- 先保证剧本意图和导演可执行性，再研究/集成外部项目；参考图库、账本、状态机、费用门禁作为后勤保障，在主线满足前不单独扩张。
- 每次要开发新功能，必须回答：它具体改善了文案、导演设计、视频生成、审片返工或合成的哪一步？若无法回答，除非属于严重安全问题，否则不是优先任务。

## Github 复用优先原则

- [CineCrew](https://github.com/Ironieser/CineCrew)（Apache-2.0）可借鉴分层 FilmDSL / 资产库 / 导演约束，但**不需要移植**完整模型执行、评片与付费重试链。
- [AI Cinematic Pipeline](https://github.com/billpar/ai-cinematic-pipeline)（MIT）的 shot-list-template.csv 已明确区分 action / physical expression / dialogue / voiceover / audio；prompt-template.md 将逐镜的摄影、位置、微动作与声音拆开，恰好佐证导演交付要强于单纯视频提示词。
- [python-jsonschema](https://github.com/python-jsonschema/jsonschema)（MIT）可用于结构合同，但不能代替剪辑师、美术师、导演的实际设计。

这些仅为公开项目结构借鉴，目前没有复制对方代码或接入其服务。

## GitHub-only 约束

2026-10-11 用户决定：直到用户明确说可以在本机部署，所有源码改进只在 GitHub；仅使用公开/合成示例，私人文案和既有 `jobs/` 不得上传。不开启 Mac 后台服务、不在 Mac 安装依赖、不提高或调用付费 API。源代码交付与未来真实视频制作必须区分。

## 验收示例

给系统一篇“一个人下班以后刷手机到深夜，最终决定拿起书”的文案：
- 好的导演稿不只写“镜头 1：男人回家；镜头 2：刷手机”，而要逐镜设计可拍时间与动作，音乐、节奏和转场，确定手机和书的双手交互与房间位置，并写清旁白/字幕、画面生成方式。
- 不能让六秒内发生七个复杂动作；也不能让手机突然移进抽屉。
- 可以把时间流逝设计为静态画面+时钟动画+灯光变化，把复杂手部动作拆段或实拍，并写明剪辑衔接。
- 人物未有参考图时，列入制作前置条件，但不能因为没生成参考图就停掉整个导演构思。

**最终成功标准：用户提供文案并完成必要的创意和费用确认，系统能交付经过审片、局部修订与合成的短视频。导演图纸完整只是其中一个阶段。当前尚未达到最终标准。**
