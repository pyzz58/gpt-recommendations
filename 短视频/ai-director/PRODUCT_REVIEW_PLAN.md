# 当前开发与审阅计划

更新时间：2026-10-12（新西兰时间）。依据用户在解释“为什么导演中转站变复杂”后同意整理并继续的决定。

## 调整的原因

前期连续修复付费、恢复、素材登记与流程问题，使工程完整性占用了过多主线时间。核心产品要回答的是：给一段文案，能否交出具体、连贯、能指导制作的导演方案。测试项数和模块数无法回答这个问题。

现有总导演、编剧、表演、摄影美术、声音、剪辑、AI 技术及 QA 分工保留。当前无需新增 Agent 或另一套执行框架；先用已有结构完成具体作品，再根据作品中的问题定向修正。

## 当前完成的交付

[《门后的信》导演交付书](examples/door-letter-review/director_workbook.md)：60 秒、24fps、8 镜头，7 个 AI 视频候选镜头、1 个后期黑场。逐镜包含情节目的、动作与表演、摄影构图、时间点、音效、后期、剪辑承接、连续性验收和失败替代。

制作决定包括：一名角色、一个房间、固定门桌窗位置；同一未拆封信封从桌面到右手再到右口袋；两组三下敲击；熄灯和曝光由后期控制。无对白、无旁白、无字幕、无配乐是本片的明确选择，不能推广为所有题材的默认模板。

本轮是当前会话助手编写的候选，使用既有 director_v2、director_workbook、continuity_contract；没有用预写十岗位响应冒充 DeepSeek 真实创作。原文、基础稿、专业稿、编译 JSON、人读版及验证记录位于同一示例目录。

在隔离 Linux 开发环境完成基础分镜校验、专业稿校验、完整物理连续性检查、严格导演编译，以及源文哈希/重编译一致性检查。结构检查无错误；8 个“尚未审阅”提示保留。没有对运行模块作改动，没有新增第三方依赖。

[《先吃饭》](examples/dinner-dialogue-review/director_workbook.md)已完成48秒、6镜头的双人对白候选，逐句区分女儿回忆VO、母亲画外对白和出镜对白，提供配音交接表与计划字幕SRT。原文/语音/字幕核对、严格编译通过；尚无实录、口型或视频验证。

它实际暴露并修复了AUD-026：校验器将“等待”误当未填内容。新增两项回归，隔离Linux全量573项通过。保留现有sync_dialogue字段的命名局限：画外对白也在该轨道里，不能仅按字段名决定做口型，应读取明确交接说明。下一项技术改动如有需要，应在既有结构可靠保留语音类型与说话人，不再添加独立执行框架。

文字样例无需等待私人存储/真实身份系统部署，也无需先生成角色参考图。真实付费执行仍必须遵守现有安全限制；不把“先交作品”解释成绕过门禁。

## 当前还存在什么问题

1. **完整自动创作的稳定性尚未证实。** 本轮证明当前会话可以完成一个具体候选，并且已有编译器能承载它；不证明十岗位模型已能重复地产出同等质量。
2. **文字合理不保证画面可生成。** 拾信、收入口袋、脸部跨镜一致性和黑暗细节需要实际素材验证，现阶段已写清失败替代。
3. **节奏与观众感受没有实片证据。** 特别是 29–35 秒黑场、敲击声的手机播放可辨性，需要视听审阅；不得自报艺术评分。
4. **当前样例覆盖面有限。** 已有无对白悬念与双人对白两种文字候选，仍不能代替真实媒体和讲解图形等任务的验证。
5. **真实生产基础仍有缺口。** 长期私人保存/备份、真实身份与供应商账单验收继续待办，Issue #1 保持 P0 OPEN。

[AUDIT_FINDINGS.json](AUDIT_FINDINGS.json) 现有 26 项：13 fixed_regression_verified、4 open_confirmed、6 investigate、3 blocked_real_media。不能将后两类统称为已经证实的程序故障，也不能因改变开发顺序标为解决。

## 暂缓项与例外

暂缓新的编排框架、更多角色、通用素材平台、额外预算层、部署自动化和没有具体风险依据的覆盖率扩张。已确认会泄露数据、造成误扣费或丢失成果的缺陷仍及时处理。修复先定位具体问题，优先参考成熟 GitHub 方案并最小复用。

此次沿用已有连续性/时间线设计，不引入外部框架。单纯编写样例或整理文档无需重复创建“技术选型项目”；真正改动运行实现或引入依赖时继续执行既有复用审查。

## 阅读与状态规则

- 以当前 README 和本计划作为入口；历史版本记录继续保留，旧“最高优先级”不能盖过本次用户决定。
- production_blueprint_ready 仅表示文字结构完整；human_approved 和 media_generated 保持 false，直到对应事实发生。
- 人读版是基于同一基础稿与专业方向稿整理的交付说明，机器 JSON 由原编译器产出；改稿时两者必须同步，不覆盖用户已批准版本。
- 本轮不操作用户 Mac，不提交私稿，不复用临时 API Key，也没有新增 DeepSeek 请求。
