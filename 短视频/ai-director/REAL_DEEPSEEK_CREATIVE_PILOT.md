## 第一轮固定实验

- **供应商**：DeepSeek 官方 `https://api.deepseek.com/chat/completions`（真实调用必须走受信任的私人执行环境，禁止 GitHub 公仓 Actions）。
- **模型**：`deepseek-flash`（DeepSeek-V4.1-Flash）。
- **文案**：完全虚构「门后的信」；见代码 `live_pilot_readiness.PUBLIC_FICTION`。不使用用户上传的《上学以后的孩子》，不使用医疗新闻或第三方真人素材。
- **实际目标**：总导演 `director_brief` **一次请求**、剧本编辑 `script_edit` **一次请求**。严格先后依赖；不是十个模型乱跑，不请求视频生成。
- **建议实验总预算**：人民币 ¥2，仅用作**规划上限**；必须先由可信私人系统和用户逐次确认费用与允许传输的文本。不能仅凭本文件或聊天中的“同意继续”发包。
- **模型输出限额**：每次最多 8192 输出 tokens。首岗的请求和费用预留可在 CI 预检；第二岗须等第一岗真实内容形成后才能精确计算，不能把第二岗提前宣称“已测算”。**输出上限不是付费硬限制**，实际费用可能超出本地字节估算，必须同时使用供应商账户侧额度管理并按实际账单核对。
- **所有结果为真实 AI 提出、未经审稿的候选设计**；真实性与模型响应率须从实际网络返回取得，当前没有任何真实结果。

## 使用前唯一的代码检验

```bash
# 仅在允许的运行位置进行本地离线预检，不会联网也不会扣费。
python live_pilot_readiness.py --public-fiction-only \
  --out /private/safe/location/preflight.json
```

说明：这是说明命令，不要求用户现在在 Mac 或公有 GitHub Actions 执行。GitHub CI 将公开虚构素材的预检结果放在同一个 **SYNTHETIC-NOT-REAL-AI** 示例制品中；仅保存 hash、费率、预留近似值、阻断原因和任务阶段，没有原文、API key、完整 prompt、模型返回正文。

**真实请求仍未具备两个关键条件**：受信任的私人执行环境及其安全 DeepSeek API 凭证，以及该环境中核实的每次隐私/消费授权。现有 GitHub 连接权限不等于 DeepSeek API 登录，也不允许把 key 或真人原稿存到公共 Actions Secrets/日志。试验应先单独获准，然后使用已有 `agent_live_pilot.run_one_creative_task`，并保存每次模型结果所更新的完整团队状态到私人安全存储，再决定是否执行第二岗。若失败，严禁自动重试或自动记作未扣费。

## 专业导演质量评分卡：必须看真实产出，不看“JSON 通过”

每项由人阅读输出后给出 0–5 分：0 完全没有、1 空话、2 有概念但不可执行、3 基本明确、4 可拍且前后一致、5 精确有创新且限制明确。总分乘以权重换算成 100 分。

| 评价维度 | 权重 | 必须提供的可观察证据 |
| --- | ---: | --- |
| 故事钩子与叙事节奏 | 20 | 前 3 秒观众能看到/听到什么、在哪里发生转折、结尾如何回收 |
| 专业场景与表演 | 20 | 逐镜角色动作，含站位、动机、微动作、连续性，没有不可拍的瞬间跳变 |
| 摄影灯光可执行性 | 20 | 构图、景别、运动触发点、光源方向与道具空间关系自洽 |
| 音频剪辑/后期逻辑 | 15 | 旁白、音效与静默的理由，数字字幕交给后期，镜间切点可交接 |
| 忠于原稿与事实约束 | 15 | 关键事件、顺序、人物没有未经批准的改写；引用原文逐字准确 |
| AI 视频模型适配 | 10 | 每镜单一清楚动作、控制时长、人物道具一致性与明确失败备选 |
| **合计** | **100** | 独立评分，附原始结构化模型回答的证据（在私有环境保存） |

第一轮判断建议：
- **≥80/100 且无关键事实/版本冲突**：允许推进下一阶段的*人工*视频试制计划，不自动发送视频生成任务。
- **60–79**：记录镜头级修改意见，优先修角色 Prompt，而非再增加 Agent。
- **低于 60 或任何原文篡改/幻觉**：停止下游，保留失败样例与错误类别，人工判断修复。
- **技术 JSON 格式不合格**：模型的失败就是一条重要真实测试结果。计入失败率，**不能悄悄用另一模型重写结果后当作一次成功**。

至少在第一次实机中记录：请求模型、岗位、响应状态、输出格式合规与否、岗位强约束是否通过、来源变更数量、具体不合理镜头的例子、用户的返工要求、供应商 token 和费用估算以及实际账单差异。私人文案和完整回答不得写到公开 GitHub。
