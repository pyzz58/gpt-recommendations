# 专业影视 Agent 创作合同与交接验收 · v0.1

> 适用：`agent_team.py` 的十阶段任务、八类岗位。目标是把用户文案变成可执行、可审阅的 **导演交付书**，而非八份泛泛的分析报告。
>
> 当前仅 GitHub-only 研发：不接入模型、不读取私人文案、不在用户 Mac 执行、不调用收费 API、不生成影像、不发布。这里定义的是**未来岗位创作标准**，不是已运行的多 AI 成绩。

## 基本制度

1. **唯一权威**：原文、`plan.json`、原文事实与人物设定为上游基线；只有总导演协调修改提案，并经过必要的人审后，才可改变原稿。专业 Agent 不可自行改写配音原文、事实、镜头总时长或角色 ID。
2. **先因后果**：每个专业输出要说明“观众这一刻知道/感受/看到了什么变化”，再决定镜头、演员、音乐或动画；避免一律用“电影感、自然转场、情绪饱满”等抽象词。
3. **跨部门共享**：总导演的 `shot_objectives` 是专业岗位任务起点。岗位交付只写入 `agent_team.SPECS` 中自己拥有的字段；提出跨部门需求应交给总导演派单，而不是覆盖邻部门的成果。
4. **完整但不过度调用**：一集一次部门级任务，动作/摄影/声音可在导演锁定后并行准备；只有受影响镜头及必要的邻镜重做，避免 `镜头 × 岗位` 的无效重复调用。
5. **三类验收分开**：结构字段校验通过 ≠ 艺术与可拍性通过 ≠ 真人批准/真实模型试制通过。阻断项目须明确标注，不能自动设为已完成。

## 部门创作与审片合同

| 顺序 / task_id | 要解决的电影问题 | 具体交付标准 | 需要交给下一岗位的信息 | 不得冒充的结果 |
|---|---|---|---|---|
| 总导演开题 / `director_brief` | 谁看、为什么看完、情感曲线及不可改动的事实是什么 | 目标观众、独特的核心冲突、结论、视觉表达原则、事实风险和不可改范围 | `creative_brief` | 已经过用户认可的剧本 |
| 剧本编辑 / `script_edit` | 开头如何抓住注意力，后续信息为什么值得继续看 | 钩子、节奏分幕、前后因果、取舍理由、修改原文的**提案**；区分旁白与出镜台词 | `story_treatment` + 待批的 `source_change_proposals` | 擅自修改权威原文 |
| 总导演锁定 / `director_lock` | 整片风格是什么，每镜为何存在 | `global_direction` 的情绪弧线、视觉/声音语法、图表安全和参考策略；逐镜 `emotion`、`observable_turn`、`visual_focus` | `shot_objectives`，可审查的统一导演圣经 | 通过编造细节把所有镜头填满 |
| 动作表演 / `acting` | 人在画面中实际如何移动、触碰、停顿和反应 | `staging`、`performance`、`beats`、`continuity`、`shootability`；实际时码、左右手/道具/位置、开头和结尾可见姿态、复杂动作拆段或回退方案 | 动作起止时刻、可观察切点、道具状态、可拍性风险 | 只写“自然走动”“生动表演” |
| 摄影美术 / `camera_art` | 观众被引导看哪里；画面为什么采用此构图 | `camera`、`art`；景别/角度/运动起止/演员与道具空间关系/灯光来源/主色与反差/镜头间视觉连接 | 镜头的构图锚点、景别变化、相机运动可实现性 | 所有镜头统一“电影级画质” |
| 声音导演 / `sound` | 每个声音在何时出现、为什么出现、与画面怎样对应 | `sound`、`speech`；配音/角色对白区分，逐句精确 cue，呼吸停顿、环境底噪、音效触发、BGM 情绪转换、字幕 cue | 声画时间窗口、跨镜延续建议、需要混音避免的冲突 | 未试听就声称旁白节奏完美 |
| 剪辑动画 / `editing_animation` | 为什么在这一帧切、下一镜如何回答上一镜 | `editing`、`animation`、`graphics`；实际动作末/首 beat 对接、具体可观察切点、J/L-cut 或明确 none、动画关键帧/图形层、AI 视频与静态图的风格合成方案 | 可执行的剪辑决策表、叙事桥接、分层图形与字幕安全区 | 重复套话“平滑衔接” |
| AI 技术导演 / `ai_technical` | 这镜该用 AI 视频、静态图还是后期合成，交给制作端什么指令 | `generation`；逐镜 route、所需参考人物/场景/道具资产、生成镜头候选 Prompt 或后期工单、失败时降级路线、不能在视频模型里生成的准确文字和数据 | 与供应商无关的素材需求/可执行工作单；区分待核验和已具备 | 已生成视频、已锁脸、已获授权 |
| 独立 QA / `quality_review` | 是否忠实原稿、能拍、能剪、各岗位结果是否矛盾 | `qa_report`；逐镜引用具体问题、严重程度、责任 `task_id`、关联镜头、建议修改、阻断理由；QA **只读** | 总导演可据此定向返工 | QA 自行修改所有部门或签发用户批准 |
| 总导演终审 / `director_final` | 是否形成统一且有创作理由的专业导演设计 | `director_decision`；接受供**用户审阅**或明确返工、说明冲突如何解决、哪些假设未实测 | `director_workbook.json/.md` + 风险/待确认项 | 人审通过、付费授权、已制成影片 |

## 全片交付书的逐镜最低质量标准

每个镜头最终让人能直接回答下面 10 个问题：

1. **剧情**：这一镜为什么存在？观众此刻的情绪、信息、疑问会怎样改变？
2. **画面**：主体是谁或什么、在什么环境、第一帧与末帧是什么、重点落在哪里？
3. **动作**：实际何时做哪一个可观察动作？人、手、道具前后状态一致吗？
4. **摄影**：景别、角度、运动与开始/停止时机如何支持戏剧目的？
5. **美术**：布景、光源、色调、人物衣着怎样跨镜一致；何处允许有动机的反差？
6. **声音**：旁白/台词的准确内容与时码、BGM/SFX 的进入退出、字幕如何同步？
7. **剪辑**：以哪一个真实画面或声音事件切走？下一镜接住了什么问题或动作？
8. **动画**：是否要动画或图表？若要，各层从第几秒到第几秒出现；若不要写 `none`。
9. **制作**：AI 视频、静态图、后期合成、实拍插入等方式各自承担什么？需要什么素材？
10. **验收**：什么可观察证据表明该镜成功；哪些是未核对、待试制或版权待审？

不能回答的问题归入 **明确的待办或阻断**，不应填入自信但空洞的虚构描述。

## 典型跨部门冲突与返工路线

- **动作与剪辑冲突**：剪辑建议“接住杯子的瞬间切走”，但动作部末 beat 只写了“伸手”。先退回 `acting` 给出可见握住动作及时间，再由 `editing_animation` 更新切点，`ai_technical` 与 QA 重审；保留无关的摄影/声音结果。
- **图表与视频冲突**：摄影要求模型现场生成准确中文医学统计。由 `ai_technical` 改为静态/后期图层，并让剪辑动画提交图层入出时间；关键研究数字仍需人工核对。
- **旁白与时长冲突**：声音部的准确 cue 超出镜头，先由总导演判断应否修改分镜/节奏或提出原稿删减建议；不能由声音部悄悄删改用户原文。
- **人物与道具冲突**：动作部声称左手从未放下手机，但后续画面要求双手持物；QA 指明镜头和状态，导演发出限定范围返工。

## 接入现有代码的验收边界

- 岗位字段、顺序、依赖、提交、版本与局部返工以 `agent_team.py` 实际 `SPECS` 为准；本文件不是独立运行框架，也不修改现有 API。
- `assemble_direction` 必须走既有 `director_v2.validate` 与 `director_workbook.compile_workbook`；剪辑时间线、动作可拍性、跨镜 `narrative_bridge` 及来源安全由既有模块分别审查。
- 未来如果写模型提示词适配器，应从本合同派生 **岗位专属上下文 + 字段白名单 + 质量检查表**，给 QA 真实结构化结果，拒绝让总导演与岗位自行随意覆盖共享事实。
- **创作完整、结构完成、剪辑交接就绪、用户批准、参考资产已核验、付费许可、媒体已生成** 必须是分开的状态；任何一项不得因其他项为 true 自动变成 true。

## 当前状态（2026-10-11）

本次增加的是**专业创作质量与岗位验收规范**，不是新 Agent 运行器。本文件本身不证明模型能按规范成功完成创作；真正的模型调用、真实文案测试、预演和人审都属于后续单独授权的工作。
