# 编剧交付给总导演：单一职责与验收（2026-10-13）

## 唯一目标

**用户原文 → 专业编剧形成完整剧本 → 既有总导演直接使用。**

本模块不创建新导演/摄影/剪辑/动作 Agent，也不负责 Seedance 提示词、视频生成、演员锁脸、布光或剪辑。镜头生产仍交给既有十阶段团队。

## 新增的正式交接接口

1. 原有 `screenplay_adaptation.build_review_packet(plan, original, proposal)` 负责 **剧本稿**、原文完整性追踪、场次/对白/动作、剧情合并拆分重排和基础时间线预览。
2. 新的 `screenplay_director_handoff.review_form(packet)` 为所有提案中的增删、重排、新对白、改旁白创建 **逐项待审** 决定，默认没有任何同意。每条变更绑定指纹，防止改稿后误用旧审核。
3. `prepare_handoff(original_plan, original_source, packet, review_decision, cast_bindings)` 重新从原稿计算并核对全部剧本、Fountain 文本和已编译镜头，核对每个说话人与稳定角色 ID，检查明显不可能的对白语速，沿用原 `agent_team.start` 重新建立新版本导演任务账本。
4. `director_request(handoff)` 调用 **既有** `agent_role_contracts.build_role_messages(..., task_id="director_brief", source_text=screenplay_fountain)`：交给总导演的 `original_script` 现在是 **完整的改编剧本**，不再是原始散文，也不会仅给原文分句占位；旧稿仍可通过来源哈希/改动账本追查。
5. 模型 system 指令明确提醒总导演：以新剧本为规划依据，负责导演创作而非重新编剧；若遇到剧本逻辑矛盾，应退回编剧并说明，不能偷偷改台词、增删剧情。

最小交接数据：`screenplay_fountain`（完整场次、人物台词、旁白、动作）、`screenplay_story_spine`、`screenplay_scenes`、`reconstructed_base`（新节拍与时长/来源对应）、`crew`（原有导演团队待执行账本）以及审稿/来源摘要。

## 明确的验收界限

- **已在代码中实现**：编剧剧本内容真正进入总导演的角色消息；现有十阶段结构未增加任何岗位；新分镜与原稿关联；角色身份映射及超长台词机械拦截；旧版本篡改/错集/漏审拦截。
- **不等于已经完成人工真实审批**：传入的 JSON 审稿决定仅能检查字段和来源一致，**不能验证是谁作出的决定**。需要私有操作台才能实现可信身份/授权；不得自称取得用户签名或同意。
- **不等于创意质量成熟**：剧本是否有真正的戏剧价值、人物矛盾是否充分、某个改编是否比原稿更优秀，只能通过实际剧本编辑与人类审稿验证；全量单元测试不能代替审稿。
- **不等于真实导演已执行**：`director_request` 只构造即将传给既有岗位的模型消息，不调用收费模型、生成视频或占用 Seedance 额度。
- **长篇来源截断风险仍存在**：旧 `article_intake.prepare_episode` 有旁白字数、镜头数及 75 秒预览时长限制。小说长稿不能把这个缩略版当作已完整阅读和改编；下阶段需要扩展为真正覆盖全文、可选择章节或故事段的编剧入口，然后继续同一套编剧→导演审核合同。

## 公开虚构验收样例

`examples/dinner-dialogue-review/`：《先吃饭》保持源台词，从开场重排、合并问答到把“手机翻面”变为无对白动作节拍。测试检查其全部角色 ID、来源摘要、完整 Fountain、44 秒新编排与真实总导演 Prompt 均一致。此样例绝不证明对任何长篇小说或私人文章的实际艺术质量。

## 下一步只围绕编剧继续

1. 在单一长篇稿上验收：全文摄入、主题/人物/场次信息不丢失；不是只取开头 185 个字。
2. 用真人可审阅的剧本评价准则评估“是否可交给导演”，重点是人物动机、矛盾发展、因果、节奏、对白真实性与可拍行动，而不是字段是否齐全。
3. 通过私有审稿确认版本后，将这份剧本交给既有导演创作岗位进行实际文本创作并记录是否仍需补写剧情。
