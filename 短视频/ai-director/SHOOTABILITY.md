# AI 短视频导演中间层：单镜头动作可拍性、双手道具与拆段制作

> **核心产品不是 AI 视频模型，而是用户给一篇文案后，系统输出可指导 AI 视频工具及后期制作的完整专业导演工作单。** 本模块仅检查导演创作中是否存在明显时间、动作和道具矛盾；不替代艺术设计，不运行视频模型，也不会因此产生费用。

## 为什么需要这个模块？

之前 S09（右手拿手机、左手拿书、人物起身）与 S10（走动、放书、把手机放进抽屉）的例子说明：**一镜的 6 秒或 7 秒都可以写出很多动作，但未必真的适合一次 AI 视频生成。** 导演必须决定哪一段动作属于同一条表演、同一只手何时空出来、物体何时从哪转移到哪，以及复杂段怎样拆开拍/剪。

`director_shootability.py` 采用**显式结构化动作单**，而不是从中文描述中猜难度。每个真人 AI 视频镜头的每个导演 `beats[]` 节拍，至少须登记一条具体动作或有意保持姿势的单元，确保没有被遗漏。纯二维图形、静态后期、不涉及人物的镜头**不强制**虚构人体动作。

### 逐拍动作描述

```json
{
  "shootability": {
    "mode": "single_take",
    "fallback": "若手部遮挡失败，拆成先取手机与后取书两条可剪接素材",
    "action_units": [
      {
        "id": "ACT01",
        "beat_index": 0,
        "actor_id": "CH_MAIN",
        "hand": "right",
        "prop_id": "PROP_PHONE",
        "from_s": 0.0,
        "to_s": 0.9,
        "action": "右手从扶手上取起手机",
        "visible_result": "手机完整进入右手握持状态"
      },
      {
        "id": "ACT02",
        "beat_index": 0,
        "actor_id": "CH_MAIN",
        "hand": "left",
        "prop_id": "PROP_BOOK",
        "from_s": 0.1,
        "to_s": 1.0,
        "action": "左手握住茶几上的书",
        "visible_result": "书在左手，桌上不再有第二本书"
      }
    ]
  }
}
```

这里只是字段示例，**ACT01、ACT02 的时间与真实分镜必须再核对**；两个 `prop_id` 需要事先登记到 `base.continuity_contract.props`。一个真实 6 秒镜头如果有多个节拍，须继续登记其余节拍，而不能只用上面两个动作冒充完整导演稿。

- `mode` 可选 `single_take`、`split_stitch`、`static_edit`、`post_composite`、`practical_insert`；实际模型/媒介路线仍以既有 `generation.route` 为准，不把这项计划当成真实执行。
- `hand` 选择 `left`、`right`、`both`、`none`；人物起身/步行/保持姿势等可以用 `none`，并写清动作结果。
- `prop_id` 仅是道具唯一标识，不是设备上传地址。没有道具可填 `null`。**未登记的道具会被标记为待补。**
- 时间 `from_s/to_s` 是**相对本镜头**秒数，必须位于所选 `beat_index` 的时段内。

## 机器可发现的矛盾

| 审查项目 | 机器处理 | 说明 |
|---|---|---|
| 真人 AI 视频镜头没有动作清单 | 待补设计 | 不把旧稿视作失败成片；但不能宣称可交付制作 |
| 有动作节拍未登记动作/静止单元 | 待补设计 | 防止只填写一个简单动作就假冒全镜可拍 |
| 同一只手同时间做两项动作、占用双手又用另一只手 | 阻断 | 建议导演调整动作起止，或重新分镜 |
| 左右手同时完成不同动作 | 可以 | 合理双手并行不应误报为冲突 |
| 同一道具被左右手同时操作 | 人工复核 | 可能是合法交接，不能一概当作错误 |
| 道具操作短于 0.55 秒 | 人工复核 | 经验性高风险信号，**不是视频模型能力上限** |
| 2 秒窗口内开始至少三项精细道具动作 | 人工复核 | 如果坚持 `single_take`，必须提出具体 `fallback` |
| 拆段时有时间缺口/重叠、无衔接说明 | 阻断或待补 | 拆段方案必须覆盖完整镜头 |

### 拆段制作要把“分段”写具体

选择 `shootability.mode="split_stitch"` 时，`segments[]` 至少写两段，必须首尾相连、覆盖原镜时长，且每段明确 `route` 与 `join_rule`。

```json
{
  "mode": "split_stitch",
  "segments": [
    {
      "id": "TAKE_A",
      "from_s": 0,
      "to_s": 3,
      "route": "ai_video",
      "join_rule": "固定右手握手机的结束姿态，利用人物起身动作作下一段的剪辑匹配"
    },
    {
      "id": "TAKE_B",
      "from_s": 3,
      "to_s": 6,
      "route": "edit_composite",
      "join_rule": "第二段开头接相同右手握持状态，人物站立姿势连续，检查书仍在左手"
    }
  ]
}
```

示例仅用于说明如何写制作计划，**不代表视频已经按这样的拆段方案生成或通过 AI 模型实测**。

## 三层不同的完成概念

1. `creative_design_complete`：每镜有动作、剪辑、动画、台词等主要导演栏目。
2. `editor_handoff_ready` / `narrative_handoff_ready`：逐秒声音、剪辑与相邻镜头叙事交接具备结构。
3. `shootability_structure_ready`：具体到人/手/道具的动作拆解、时间和必要的分段方案完成，没有明显矛盾。

只有上述所需栏目都满足，并且没有待复核的明显复制套话，`production_blueprint_ready` 才可能为 true。**它只是创作蓝图结构完整，不等于镜头实际生成成功、人脸一致、电影语言优秀或用户已批准发布。**

交付书会为每镜增加“动作可拍性”区块，列出单位时间动作与警告。AI 制作路线转换与素材上传仍由其他辅助模块决定，且本阶段全部处于离线、禁止执行状态。

## 质量测试

新增 `tests/test_director_shootability.py`（23 项公开合成单元测试用例）测试双手安排、动作覆盖、时间越界、道具登记、密集操作、fallback、拆段覆盖与集成导演交付书；同时更新跨镜头导演的“全量创意蓝图”合成夹具，使其主动写全真人节拍动作。

**本轮尚未获得 GitHub 最新完整源码的统一 CI 运行结果；有测试代码不等于这些测试已经通过。** 正式宣称可部署之前，需在无收费模型的隔离环境完成整仓测试并人工审看报告。
