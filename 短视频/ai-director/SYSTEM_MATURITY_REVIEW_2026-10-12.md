## 结论

产品目标已经回到“用户文案 → 专业导演设计 → 视频 API → 审片/局部返工 → 剪辑成片”。当前是**具备导演制作包和单镜技术试验能力的研发原型**，不是已经完成、只差账号测试的成片系统。

结构化设计与模拟交接有较多验证；完整创作质量、人物跨镜一致性和真实成片仍未证明。三个入口尚需开发者接力：旧 local_director.run 的 series/plan/direction 链、来源锁定的十阶段专业团队、video 单镜任务。保留多岗位方向合理，当前应补交接和作品输出，不增加岗位或通用框架。

## 本次新增确认的三处缺陷

所有复现仅使用公开虚构《先吃饭》及 mock。诊断脚本：[audit_probes/system_maturity_20261012.py](audit_probes/system_maturity_20261012.py)。这是观察脚本，不是已修复回归证据。

### AUD-030 / P1：人物和部分结构化摄影指令未进入生成请求

位置：director_v2.compile_package → seedance_adapter.prepare_shot。

复现：只修改母亲 description/wardrobe，或修改 camera.screen_axis、focal_length_mm、staging.spatial_constraints 和 art.scene_geometry，生成请求的 body 逐字不变，request_digest 却改变。当前 S02 请求也没有母亲“短发、米色开衫”的完整人物定义。

影响：导演/摄影以为改了人物或机位，供应商实际收到的仍是旧指令；有相同自然语言重复信息的样例会掩盖缺口。现有 prompt 确实传了一部分构图、运动、环境和节拍，不能说所有摄影设计都丢了。

修复验收：明确结构化规格与文字说明冲突时的处理，将实际入镜人物、服装、必要机位/空间锚点编译进请求；修改关键字段必须改变发送内容，冲突应提示，而不靠把整份 JSON 无选择塞给模型。

### AUD-031 / P1：原生声音没有接收完整声音设计

位置：同上。native_dialogue 开启 generate_audio 并加精确对白，但未完整编译 sound.ambient/music/effects。

复现：把 S02 的 ambient/music 改成不同的明确指令，请求 body 不变；《先吃饭》原设计的“none：无配乐”没有进入生成提示词。beats.sound 虽有部分声音线索，不能替代完整声音设计。

影响：原生生成可能添加不希望的配乐或缺少指定声景；同时后期单仍含录音/口型安排，需明确谁负责最终声音，以免重叠。

修复验收：按 native/silent_post 区分声音职责；原生请求明确禁止/要求的配乐、声景与声效，后期单明确保留/替换哪些轨道。仍不保证模型必然遵循，需实际审听。

### AUD-032 / P2：重新查询不保存更新的成功结果

位置：seedance_adapter.query_once 的 “if not result.json.exists()”。

复现：同一任务连续两次 succeeded，第二次返回不同 video_url，本地 result.json 仍为第一次地址。两次是 GET，只有一次 mock POST。

影响：如果供应商返回更新地址，操作者查询后仍会下载旧地址。**本次只证明丢弃新地址，不宣称供应商保证刷新过期链接，也不宣称能恢复已被删除的结果。**

修复验收：成功查询结果按版本追加保存，下载显式选择最新已校验结果；保留旧记录与已下载视频，不重新提交视频任务、不覆盖已审片媒体。

## 其他已确认的流程缺口

1. **没有统一的真实制作入口**：local_director.run 走旧三段创作链；agent_live_crew 只运行一个岗位；video 接受手动提供的 base/direction。现有 local_ui 只保存文案并产生任务文件。归入 AUD-029，避免重复造问题编号。
2. **参考图不是完整生产通道**：输入 URL 列表不能表达“图1是哪位演员/哪版服装”，没有接上来源绑定的参考清单和私有素材。继续归入 AUD-003。
3. **改编权过窄且申请改编后的操作不完整**：editorial_storyboard.propose_directed_storyboard 保留旁白与时长，后续专业岗位受锁定 base 约束。保留原稿是对的，但要有明确候选修订/接受/重新锁定流程，允许导演在获准后重排镜长、拆并镜和补演员，不能把原始规则分镜永久当成最佳剪辑。
4. **文档存在历史状态混杂**：较旧文件仍写“尚未调用 DeepSeek”，更新文件记录两岗真实试验。报告采用运行日志和当前源码，旧规划文档不当作当前状态；优先维护单一最新状态入口。
5. **覆盖率统计范围落后于新增视频模块**：更新 AUD-015 的调查记录。609 项包括相关测试，但全局百分比不能替代新链路缺口诊断。

## 下一步只补主线，按此顺序

1. **先修 AUD-030/031**：保证人物、摄影及声音修改确实进入当前单镜请求；为关键字段变更增加最小回归。然后修 AUD-032，确保新 GET 结果可用于下载。无需账号即可完成。
2. **准备一次 S02 实测**：核对账号区域、确切模型权限/单镜报价和预算，配置已有单镜命令运行的私人环境。用户只需完成账号开通与额度选择；程序接入和运行配置由开发方承担。第一镜可用已写好方案，不要求先重跑十岗。
3. **两镜试片与后期最小输出**：锁定人物/场景参考，把 S02/S03 串起来；接真实解码、实测时长、字幕和简单拼接，保留两镜各自的候选版本。优先评估已有 FFmpeg 等成熟工具的最小集成，不新增影视编排框架。
4. **一条完整短片、再换一篇新稿**：接全片声音和后期、补真实团队统一入口，验证文案到成片可以重复完成；记录用户需额外补设计的次数、逐镜返工原因和实际花费。

## 关于账号与 API 的明确答复

开通账号、模型权限和可用额度是用户侧准备；密钥配置到实际私人运行环境即可，不需要粘贴在聊天里。但“拿到 Key”不等于整套产品完成。

Seedance Key 负责生成视频；若要系统自动完成总导演与专业岗位创作，还需独立的文本模型接入（当前代码为 DeepSeek 路线）。已准备好的 S02 可以先只测视频，不必为此立即再跑整个创作团队。运行部署、素材回收、版本和合成属于产品应完成的工作，不能全部推给用户。

本轮新增项全部标记开放，未关闭任何真实生产或媒体验证事项。没有收费调用、发布或 Mac 操作。
