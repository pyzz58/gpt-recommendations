# QO-D19｜合成视频声音、字幕与真实媒体验收分层

状态：2026-10-14 开始第五阶段；只对公开合成短片中的帧级事件做实际解码验证。未核验真人配音、唇形、角色演技、商业使用权，也未进行任何 Kdenlive 桌面 GUI 导入。

## 1. 源的权威性

此前已审编剧剧本、QO-D19 `director_speech_cues.py` 逐句 source-exact cue、QO-D09 帧级电影导演工作单以及最终QO-D13全片时间预算仍是生产唯一权威。新AV验收脚本不接管或自动生成创作时码，不允许把过长台词切碎后声称已经合理；真实演员的发音速度、情感停顿、口型匹配仍是后续专业岗位和人类导演审核。

## 2. 公开合成的可复现媒体测试

1. QO-D09 用同一个原生OTIO导入数据核验先生成3秒红、绿、蓝三镜真实视频硬切，FFprobe精确核验90帧/30fps以及实际色彩像素。任何画面镜头短缺、错序、来源篡改或强制非硬切转场均直接失败。
2. 创建3秒48kHz、mono、16-bit PCM纯合成测试音（正弦音调），明示两段事件帧 `[10,25)` 及 `[43,55)`；每帧1600采样，处于事件帧内必须有充分声能，事件帧外必须是静音；提前、超长或遗漏任一帧自动阻断。
3. 字幕事件帧 `[12,26)`、`[42,57)` 分别将准确的公开虚构英文字幕通过QO-D19来源精确的SRT编排交给FFmpeg/libass真正烧录。回读RGB并比较同一颜色镜头在字幕前与字幕中的底部真实像素；文件存在但没有视觉叠字不能算通过。
4. FFmpeg实际把已证实的画面、PCM声音及libass字幕合成Matroska，FFprobe核验仍为90帧；重新解码整条声轨，并与合成源WAV进行逐字节一致性比对，不容许时间轴自动补音、截音或改变样本。
5. 以上只证明***对于预先已给定的时间码***，我们的媒体流水线能正确合成测试音频与字幕，不证明语音识别、中文排版、唇形帧级匹配、实际音频从真实演员生成或复杂转场已经可执行。

## 3. 阻断测试

- 缺FFmpeg、FFprobe或libass时 GitHub CI必须报错，不能把媒体验收全部标 skipped 后冒称通过。
- 合法视频/音频文件名由安全白名单限制。拒绝目录穿越、覆盖、不同工程帧率、错误文件SHA、发布许可伪造、声音片段越窗、片段空缺和字幕重叠。
- 合成测试不处理真实人声时长估算、对白跨镜J/L bridge、连贯表演、配乐版权、二维/三维动画综合声画、1.8秒真实演员鸣谢/文献页。
- 真实NLE软件打开工程、音画播放/导出、三方盲评仍未进行。效果与转场在不同NLE中不可保证等效，还必须由导演、声音和剪辑部门在目标软件中另行核验。
