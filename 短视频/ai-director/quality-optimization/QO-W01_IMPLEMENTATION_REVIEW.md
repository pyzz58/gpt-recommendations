# QO-W01｜全稿核心思想保留：第一次修复与审阅证据（2026-10-13）

> 本文只评估新的语义追溯**能力**，不宣称已证明作品或 AI 编剧达到一流质量。主账 `QUALITY_ISSUES.json` 中 W01 在独立真人/授权模型盲评完成前保持 **in_progress**。

## 1. 原先为何错误

原有 `screenplay_fulltext_intake` 能计算完整原稿段落和 `source_ids`，`screenplay_adaptation.validate_proposal` 能核查「所有来源 ID 被引用或有明确省略」。**但原稿最后开放的问题可以被编剧变成一个相反的确定结论，仍通过 100% 来源 ID 覆盖**。这是「引用记录完整 ≠ 原作者的中心观点被忠实表达」的真实结构性缺陷。

## 2. 只改编剧、不占导演职责的解决方案

`screenplay_semantic_fidelity.py` 增加一个严格的、**审稿前**的原文思想追溯流程：

1. **编剧动笔前**，独立阅读者生成 `idea_manifest` 候选，逐条记录 `critical/supporting`、来源精确引文、来源单元ID、内容含义和丢失后观众会产生什么误解。每条候选与原稿和选定章节 SHA-256 绑定；候选是否足够完整还要人工核查。
2. 完整编剧请求 `screenplay_fulltext_intake.editor_request(..., source_idea_manifest=...)` 真正将该表注入实际用户消息，同时保留原文全部 `source_units`；**改编后不能临时重建一份对自己有利的思想清单来过审**。
3. **剧本完成后**，独立的反向审读请求 `build_semantic_review_request` 把原稿、预先建立的思想表、完整剧本和 beat 映射一并交给审稿角色，对每条分别标 `faithful`（保留）、`partial`（被淡化）、`lost`（遗漏）、`contradicted`（反转）。
4. 评语必须精确引用剧本文句，绑定原 source unit 对应的剧本节拍，说明损害和返修办法。缺失、假文句、错误链接、旧稿或未经处理的 **critical** 观点，会阻断新的严格导演交接路径。
5. `build_targeted_semantic_rewrite_request` 把问题定点返回前置编剧，重新提交完整剧本、来源映射、独立语义审稿、专业剧本审稿和作者审核。**不会自行修改导演的拍摄/镜头内容**。
6. `screenplay_fulltext_intake.semantic_quality_director_handoff` 在严格语义审稿 + 独立剧本专业审稿 + 现有作者形式审查表三者齐备后才构造原总导演岗位请求；旧兼容入口不宣称已经经过语义验证。

## 3. 反例与当前完成证据

公开虚构素材讲「旧地图、过河速度、桥究竟要通向哪里？」：

- **旧门禁可能误过**：所有 `Uxxxx` 都出现在新剧本来源引用中，`source_omitted=0`；但最终关键剧本被改成「只要过河速度最快，目的就已实现」，这是将原文最后的**开放价值问题**错误改为确定效率结论。
- **新门禁针对性阻断**：独立审阅给 `IDEA-001` 标 `contradicted`、定位到最后一个剧本节拍和实际错误台词，`recommendation=revise`；严格导演交接返回 `FULLTEXT_CORE_MEANING_REVISION_REQUIRED`。
- **正常正例**：包含原文真正开放问题的剧本，通过内容引用/版本一致性检查后，可形成 **仅供导演规划** 的交接；没有真实作者身份认证，代码也不会自称作品艺术水平达标。
- **反作弊**：漏掉关键审稿项、伪造剧本引文、错误节拍 ID、误用旧版本、伪造原文引文均阻止通过。即使不称职审稿者撒谎并标 `faithful`，本模块仍明确报告「人类语义正确性未验证」，**不会用哈希或字符串匹配证明思想正确**。

预计脚本验证：`tests/test_screenplay_semantic_fidelity.py`；执行期使用 GitHub Actions 可核验提交、脚本数量与覆盖率。

## 4. 未解决且不得关闭 W01 的事项

- **作者/独立人的盲评**：预先抽取的核心思想清单是否完整、编剧改稿是否真正保留思想的关系，必须对至少 3 种题材（fiction、documentary、essay）以及无标题长文进行**遮蔽版本来源的独立审核**。当前只有公开合成回归，尚无实际被认证的独立审稿者或授权私人稿件实测。
- **失真漏检率**：当前批注由审稿角色产生，质量依赖它是否真的看出淡化/反转；一个坏审稿器可以错误填 `faithful`。要通过有正确答案的多案例金标基准比较漏检和误报，必要时更换模型/策略。
- **真实作者确认**：形式 JSON 审核不是身份认证。必须保持 `author_approval_authenticated=false`，不能把已给导演文字规划等同成用户本人准许出版/付费生成。
- **不同文体定义**：fiction 应评估人物选择/因果，documentary 须审查事实归属，essay 审查论证限定和反驳，W02/W07 仍应独立解决其专有缺口。

### 关闭条件

仅在正/负回归已通过、3类公开样稿+无标题长文均经独立盲审或用户认可的人工审查、关键思想丢失/淡化/相反结论能稳定发现、误伤率有样本报告，以及对应源码和质量总账有 PR/测试/审阅证据后，才能标 `complete`。

继续遵守 AI 短片特殊性：**完整文案 → 剧本场次/思想转折 → 导演分镜 → 模型片段**；不得因单个模型 4/8/10 秒等时长截断原稿关键观点。无原文证据材料时不补文献与最后一页。
