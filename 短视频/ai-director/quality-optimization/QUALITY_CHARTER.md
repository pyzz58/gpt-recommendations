## 国际导演一手深读后的权责纠正（QO-D14）

导演**不是**必须保留编剧全部节拍的制作执行员。用户要求其有权判断剧本无聊，提出删场、结构浓缩与不同长度剪辑方案（例：十分钟故事经过真实创作改写后做成3集）。专业来源支持导演参与文学修订、统筹场面调度和主导导演剪辑，但**不能把压短本身当作品价值**。本系统保留完整原稿、逐节拍编辑处置和观众获得/失去什么的专业理由；结构性变更须触发编剧改稿与独立审阅，新版确立制作权威后才进入单集90秒硬验收。DGA只是参考劳动权益，非本项目合同。完整材料见 [QO-D14_PRIMARY_SOURCE_DIRECTOR_AUDIT.md](QO-D14_PRIMARY_SOURCE_DIRECTOR_AUDIT.md)。

## 研究先于实现：从现在起每次专业质量优化的前置门禁

任何 QO 项目必须先取得**职业一手资料**，优先完整官方工作指南、可公开阅读的讲座/访谈全文、行业手册与成熟作品案例。对于**仅公开课程大纲、付费讲义、节选、新闻摘要、二手报道**，必须标注获取范围，禁止虚构“全文读完”或将讲师个人观点宣称为全球硬标准。随后逐函数分析现有代码/真实产物，区分**专业创作不足**与**字段/流程安全不足**；必须列出职业方法原理→当前缺口→因果根因→创作层面的方案→可观察的作品验收，才允许增加提示词、schema、Agent 或校验代码。无论是 CI、哈希、来源 ID 或评分表，都不能替代对原稿到影像作品的专业审读。**暂存未完成研究的代码为 Draft，不得为了测试全绿提前合并。**

W01 已完成的专项原始资料深度审核及针对性方案：[QO-W01_PROFESSIONAL_PRIMARY_SOURCE_AUDIT.md](QO-W01_PROFESSIONAL_PRIMARY_SOURCE_AUDIT.md)。过早的追溯代码 PR #24 仍在 Draft，需以此审计为依据重新评估。

# AI 导演系统｜质量优化阶段总纲（2026-10-13）

## 2026-10-13 新增两条硬性质量约束

1. **编剧要尽可能详述**：完整剧本+逐场/逐节拍说明，写清环境、可见行动/反应、人物动机、论证因果、情绪变化、对白/旁白、沉默意图、重要道具和前后连续性，尽量让总导演能看懂**每场到底发生什么、为什么发生**。严禁只交摘要、台词列表、镜头提示词或无意义的字数堆砌；并不代替导演机位、灯光和模型片段设计。
2. **单集视频时长绝对不超过90秒（1分30秒）**，包含全部镜头、必要片头、回顾、过渡、结尾以及存在时的末尾出处页。**整部编剧剧本不受90秒约束**：十分钟脚本交给导演后，由导演结合叙事、人物和思想自然转折自主决定上/下、上/中/下或更多集数；**导演拥有正式的艺术取舍和大幅压缩提案权**，可以让原稿600秒变成3集短版，但要经专业理由论证、逐节拍留/缩/删有来源的审计、编剧返修和必要的独立审核形成新版权威剧本；不是为了90秒限制偷偷删掉不可替代意义、篡改台词或自称已获批准。经审核的新制作版才要求分集完整无遗漏。超长应先分集再展开专业摄影/表演/剪辑。AI 模型每次 clip 长度与每集时长是两级不同限制。

系统严格路径：`screenplay_series_delivery.py` 的 **writer dossier → director breakup plan (<=90s) → per-episode original crew**；已有长剧本接口和旧系列 Skill 与之对齐。现有旧兼容 API 不能以单集交付绕过长剧本分集。新增质量问题为 QO-W11 和 QO-D13；情绪深度的进一步优化归 QO-W03，须实际作品质量审读，不能自称已解决。

## 一、不可变的产品目标

**用户输入原文 → 职业级编剧改编 → 职业级总导演视听设计 → 表演、摄影、美术、声音、剪辑、AI 技术、独立 QA 各司其职 → 适配第三方 AI 视频模型生成短镜头 → 真实审片、局部返工及整片后期 → 用户审阅成片。**

- 目标是让**每个环节接近国际优秀职业团队的工作水准**，而不是创建一个“万能导演 Agent”，也不是只产出漂亮 JSON 或视频提示词。
- **适用场景是 AI 短视频**。借鉴国际优秀电影编剧/导演的思想、手艺、分工、审片与重写流程；**不得照搬 90–120 分钟电影的固定时长、人物数量、三幕节点和实拍排期**。长篇作品可分集，每集长度从内容和用户/平台要求推导，不被单个生成片段长度锁死。
- **独立质量优化项目文件夹**：本目录的 `QUALITY_ISSUES.json` 是唯一权威质量问题账；`QUALITY_ISSUES.md` 是机器同步生成的可读清单；`quality_registry.py` 是变更门禁。既有 `../AUDIT_FINDINGS.json` 是**另一套技术/安全审计账**，不可删除、改名或擅自关闭。两个登记都需通过 CI。
- 专业标准是目标和审稿参照，**不是已经获得国际专业人士或行业协会认证**。不要因为增加 Skill、审稿提示词、自动测试或优秀样例，就宣称系统达到世界一流。

## 二、当前/未来的严格范围

**分批修复计划**：[EXECUTION_PLAN.md](EXECUTION_PLAN.md)。

**当前质量优化优先序**：前置编剧 11 项（QO-W01—W11）→ 总导演 14 项（QO-D01—D14）。允许并行研究相依项目，但不能忽略真正阻断项。其它 10 个 QO-F 项先保持 `audit_pending`，到其专业阶段再进行有针对性的国际标准调研与 AI 模型实测，不得误报已审计完成。

任何修改先查与该环节相关的 QO ID。若发现新问题，用下一个永不复用的 ID 追加到 JSON，注明来源与依赖，再着手开发；不能靠聊天记录取代文件。若属于旧 AUD 安全问题，两账互相链接但不重复关闭。**一次完成一个问题，就独立变更该条状态并写入证据**，不得批量宣布所有部门成熟。

优先复用已核实许可证、维护状况、供应链风险和适用性的开源项目；不要为了追求“世界一流”无限堆砌 Agent、接口或检查器。出现相互冲突的规范时，以本总纲及最近一次明确的用户决定为上层目标，并先记录冲突再修。

## 三、专业编剧的所有权

编剧负责：全文审读、原意和论证/剧情主干、适合体裁的叙事改编、角色与因果、场次、可见可听的戏剧行为、人物对白、旁白、潜台词、作品声音和结尾，以及改稿记录。

- 小说/虚构：人物选择、障碍、行为、代价、情感变化，不强制僵化的模板三幕。
- 纪录/科学史：时间脉络、原文事实与观点的区分、重现或示意标识，不能虚构名人谈话。
- 科普/议论：主问题、论证/概念层级、认识变化、信息浓度与可视化潜力，**无主角不是缺陷**。
- 必须写清重要的**叙事性动作和必要的视觉意图**，不能把编剧错误地剥夺画面表达权。
- **不负责机位、焦距、灯具、演员逐秒走位、生成模型 API 参数、剪辑工程**。可提出有意义的画面/转场建议，但具体制作形式由总导演。
- 作者原文**有资料、证据、数据、引用才保留/选择添加**；没有就不强行补充、杜撰来源或生成无依据的片尾名单。新事实只能作为清楚标记的待核实编辑性提案；正片不能冒充已证实。可选片尾参考资料仅在最后一张静态页面 1–2 秒，文字由后期实现，可读性应由真人判断。

## 四、总导演的所有权

导演负责：把**已完成并锁定的剧本**变成可感知的电影语言；选取视听主题、演员表演方向、空间/构图/剪辑布局、分镜覆盖、画面之间的连续性、审片与作品最终风格统筹，并将工作派给专业岗位。导演可指出编剧缺陷，但只能通过带有源版本与具体问题的编剧返修请求改剧情；不能在下游静默篡改台词或事实。

已有 `agent_team` 十阶段结构在完成前置编剧的交接中，原 `script_edit` 只检查**剧本连续性和遗漏**，不再次写故事，避免重复。没有经过前置编剧的旧素材保留兼容模式。

## 五、AI 短视频特有的四层制作模型

1. **完整原文**：覆盖全稿/明确所选章节，不受单镜时长限制；保留来源与删改理由。
2. **剧本场次/事件节拍**：描述故事和信息转折、对白/旁白、动作、合理总时长。**不是生成视频 clip**。
3. **导演镜头（coverage shot）**：导演依照故事功能设计多机位、反应、空镜、图文；同一场可多镜，一镜可跨多个叙事节拍。
4. **供应商生成片段（clip/take）**：AI 技术岗位按具体版本/渠道/能力表将导演镜头拆成若干模型请求，可选 Text/Image/Reference-to-Video、原生音频或后期配音，再由剪辑组拼接。**clip 时长绝不倒逼编剧删核心内容。**

官方资料说明接口**不同且会变化**：
- Runway Gen-4.5 当前支持 2–10 秒片段（对应选定模式/账户）；
- Google Veo 3.1 API 支持 4/6/8 秒，参考图与高分辨率存在特定条件；
- Kling 3.0 有多镜脚本及原生音频能力，具体镜头数量与各镜时长取决于请求模式；
- ByteDance Seedance 2.0 宣布支持文本、图像、音频、视频多模态和联合音画生成；当前项目保守 Seedance adapter 只实现 4–15 秒 single_take 子集，不代表所有官方能力。
**以上均为当时文档核对参考**，不得据此声称用户已开通对应 API、资费/配额可用或真实片段已经生成。模型版本/区域变化要刷新接口能力表。

AI 风险永远要单列：人物/服装/道具/场景跨镜漂移、双人互动与手部物理动作、嘴型对白错位、声音误读、过长复杂提示词、多镜模型误切镜、准确文字与数据生成不可靠、素材许可和生成失败的反复费用。优先使用局部重生、参考素材、必要的静态或后期方案来降低失败率，而不是把一切都硬推给视频模型。

## 六、一流目标转化为分级验收门禁

- **G0 国际标准基线**：引用来源机构/教程/访谈与日期，说明适用于短片的工艺和不能照搬的电影工业惯例；写出负责岗位与互相协作边界。
- **G1 确定性与源文门禁**：来源不丢、授权版本不变、字段与时码正确、无编造引用/错台词/模型参数越界；至少公开合成正例/反例。
- **G2 独立职业内容审阅**：编剧对场次与语言，总导演对声画构想，盲评首稿/修订稿，必须指明原文、具体问题、观众后果、定点返修与证据。不允许只给“90分”或泛泛好评。
- **G3 AI 模型可制作性**：型号、渠道、版本和真实目标制作方式核查；从故事镜头到短 clip 的分解正确；保留角色参考/音效/后期分工，若没有实际模型媒体则标“未实测”。
- **G4 真实媒体和人工验收（相关部门必需）**：经用户明确许可才发付费请求；记录片段、身份状态、音频/口型、帧/音解码、预算、失败率、选片与局部返工、真实观众/人工评语。G1-G3 **不能冒充 G4**。
- **G5 实际成片与长期质量迭代**：经授权的多类题材短片、长期重复实验、返工时长/成本和真人偏好对照。用户不要求现在完成 G5；没证据时不能宣称一流。

可以在质量改进中记录预期指标（如核心思想保留、镜头可用率、严重断裂率、盲评偏好），**必须将目标阈值、测量样本和实测结果分列**；不要把预设数字写成已经实测的成绩。自动覆盖率仅衡量 Python 测试覆盖范围。

## 七、问题清单工作规程（强制）

1. **定位**：先从 `QUALITY_ISSUES.md` 选一个 QO ID，确认岗位、用户目标、历史代码、独立来源、AI video 特征及旧 AUD 关联；`audit_pending` 不叫“发现故障”，只是尚未审计。
2. **复现与根因**：使用公开合成脚本和明确预期/实际对比；对艺术质量问题补真人可读的失败例子，不以 JSON 字段缺失代替创作质量问题。
3. **设计**：给最小必要的职业级修复，明确编剧与导演责任、模型版本/时长、是否需付费素材、下游哪些工单要失效。
4. **实施**：创建 PR；保留源码和原稿的不可篡改摘要；禁止用户私稿、账号、密钥及现实私人素材入公共仓库。
5. **验证**：新增正反测试、运行完整 CI、执行独立专业文本审稿/适用的真实媒体人审。能离线证明什么，就只记录什么。
6. **关闭**：对应项 `status=complete` 时必须有真实 GitHub PR、40位 commit、对应测试、独立审核、清楚写明的解决证明与关闭日期；导演/实际媒体岗位必须附真实媒体检验记录。**只达到部分目标时保持 `partially_addressed`**。
7. **同步**：运行 `quality_registry.py --render-board`（或等价生成），CI `--check-board` 保证 `.md` 没滞后；一条一条更新。不删除旧记录、不重用 ID。技术类修复同时检查 `AUDIT_FINDINGS.json`。
8. **复开**：新证据表明旧问题未解决，恢复为 `confirmed_open` 并保留曾经完成的 PR/证据及复开原因；不能静默抹掉历史。

**禁止**：为了指标而过度加 Agent、照搬长片模式、无真实画面却宣布“世界一流”、没有原文资料却杜撰引用、未经单独授权发付费请求、误用外部模型技术文档当用户账户实际能力。
