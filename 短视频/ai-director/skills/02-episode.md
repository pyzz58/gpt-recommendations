# Skill 02：单集内容编辑与数据账本

工作顺序：核心观点 → 观众体验 → 旁白 → 镜头目标 → 证据 ID，最后才决定 Prompt。

1. **绝对上限90秒**：全部镜头、必要的开场/回顾/片尾材料都计入；导演可将完整剧本切分成连续多集，每集能独立进入、获得阶段性进展并自然衔接下一集。开头可建立悬念/共鸣，不得为强行留钩子偷改核心事实或人物行为。必须引用权威剧本具体场次/节拍位置和同一导演系列圣经。
2. 输出完全符合现有 director.py 的 v0.1 `plan.json` 结构；与 series.json 的 character.id、description 和 visual_bible 一致。禁止凭空造不存在的参考素材。
3. 旁白不以篇幅为重：研究的人数、暴露、比较组、终点和研究性质必须准确；没有原始研究来源时 `claims.status=needs_review`。
4. 数据可删减，但在 `editorial.omissions` 明确说明删掉了什么、为什么。禁止自行把风险相对增加解释成绝对发生率。
5. 原文实际提供资料/论据且已经核实时，才可选**该集最后一张1–2秒静态页**显示简短来源；它计入90秒总上限，完整可核查资料可放视频说明。若无可靠来源，不制造证据卡。原规范中的“5秒来源页”已废止。
6. 数字动效由后期做；AI_VIDEO 只管可拍摄画面。所有文字和百分比后期叠加。
7. 确保每镜时间轴连续、总时长准确、每个人物角色ID来自 series.json。
## v0.3 P0 · 研究卡文献账本必填

如果输出 `purpose=sources` 的1.8秒（现行1–2秒规则）静态卡，`plan.json` 除 `claims` 外**必须新增**顶层 `references` 数组，每项按照卡片的 `claim_ids` 逐个建立可追溯书目：

```json
{"references":[{"claim_id":"C01","author":"首作者","year":2023,"journal":"期刊名","study_type":"RCT / 观察 / 系统综述","url":"https://doi.org/...","status":"needs_review","limitation":"研究局限"}]}
```

不要编造 DOI、作者、年份或期刊。查不到对应的真实书目时**不要生成片尾来源卡**，而是保留 `needs_review` 的事实审查待办。文献元数据可追踪不等于研究数字正确：发布依然需要原文核验。
